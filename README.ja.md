> **公式サポート言語**: 本アプリケーションは、UI表示・音声認識エンジン・AI推論回答のすべてのレイヤーにおいて、英語（English）・日本語・韓国語（한국어）を公式にネイティブサポートしています。

macOS向けのローカルファーストなマルチモーダル・デスクトップコパイロット。画面上の状況を見守り、ローカル環境内で検索可能な履歴を保持し、本当に発言する価値があるときだけ助言を行います。会話の両面を聴取することも可能ですが、マイクは起動時にはオフになっており、ユーザーが明示的に要求したときにのみ動作します。

ブラウザやElectronシェルでは実現できないネイティブ機能——他アプリケーションのアクセシビリティツリー（AXUIElement）の読み取り、CoreAudioプロセスタップによるシステム音声出力の直接取得、ハードウェアエコーキャンセレーション（AEC）、フルスクリーンアプリの前面に重なるクリックスルー対応フローティングウィンドウ——を余すところなく活用するため、完全ネイティブSwiftで構築されています。

## 主な機能

| | |
|---|---|
| **見る (Sees)** | OSイベント（フォーカス変更、ウィンドウタイトル変更、入力休止）をトリガーに、アクティブウィンドウのアクセシビリティツリーを読み取ります。Canvas描画型アプリではオンデバイスのVision OCRに自動フォールバック。高負荷なフレームレート監視（定期ポーリング）は一切行いません。 |
| **動かす (Acts)** | CoreGraphicsイベント合成とアクセシビリティAPI（AXUIElement）を連携させたネイティブGUI操作（クリック、テキスト入力、キー押下、AppleScript実行）。TypeSafe AI（Jev System Oneモデル、<200ms）による超低遅延UIグラウンディングと、キー未設定時のローカル意味一致フォールバックを完備。内蔵Copilot、CLI（`mca act`）、外部MCPエージェントから安全に実行できます。 |
| **聴く (Hears)** | ハードウェアAEC付きマイク入力と、仮想オーディオドライバを介さないCoreAudioプロセスタップによるシステム音声出力を独立してキャプチャ。「あなた」と「相手」の2チャンネルを明確に分離して扱います。**起動時は何もキャプチャしません。**音声会話（⌥⌘V）の開始時にマイクが開き、終了時に閉じます。常時キャプチャは ✨ ▸ 設定 ▸ 一般 ▸ オーディオ から切り替え可能です。 |
| **書き起こす (Transcribes)** | デュアル認識エンジン対応：完全なローカルプライバシーを保証するAppleオンデバイス `SpeechAnalyzer`、または高度な文脈理解と同音異義語の補正・不要なフィラー除去を行う **Gemini Flash 音声バッチ認識**。Appleエンジン使用時は音声データが端末外へ送信されることはありません。 |
| **話す (Talks)** | モード選択ではなく2つの独立したボタンを用意。マイクボタンは**ディクテーション（音声入力）**：Mac上で文字起こしされ、テキスト入力と同じチャットモデルに送信されます。隣の波形ボタンは**Live会話**：1つのソケット上でGeminiが音声を直接聞き取り、音声で回答。最新情報が必要な場合は自動でWeb検索も実行します。いずれのモードでも、認識された発話内容は作業中ディスプレイの下部に大きな字幕としてリアルタイム描画されます。 |
| **覚える (Remembers)** | SQLite + FTS5 全文検索、およびオンデバイスのクエリ拡張機能を搭載。完全一致だけでなく文脈の意味による検索が可能です。 |
| **助言する (Advises)** | オンデバイスモデルがすべてのスキャンを一次判定（トリアージ）し、原則として沈黙を保ちます。ゲートを通過した重要なイベントのみがクラウドモデルに送られます。チャットで「**画面を見守る (Watch my screen)**」を有効にすると、タイマー周期で画面そのものの画像も分析し、誤り・エラー・リスク・効率的な手順を発見した時のみ発言します（既定はオフ、アプリ起動時も必ずオフで始まります）。 |
| **見せる (Shows)** | ✨ メニューバーアイコンや ⌥Space からワンクリックで開くチャットウィンドウ。回答と自発的な助言が単一スレッドに整理されます。メニューバーのポップオーバーに加え、フルスクリーンアプリの前面にも常時表示でき、エディタからフォーカスを奪わず、クリックスルーも可能なフローティング `NSPanel` オーバーレイも利用できます。 |
| **共有する (Shares)** | 記録されたコンテキストおよびGUI操作ツール群（`computer`, `click_element`, `run_applescript`, `inspect_ui_elements`, `typesafe_act`）を、MCP（Model Context Protocol）サーバーとして外部エージェント（Claude Code、Codex等）に標準入出力経由で提供します。Macやブラウザを操作するツールは、`config.json` に `"mcpAllowDangerousTools": true` を設定しない限り MCP 経由では拒否されます。 |

## 動作要件

- macOS 26 以降、Apple Silicon 搭載 Mac
- Xcode 26.6+ / Swift 6.2+
- （任意）Gemini、Anthropic、OpenAI 互換、または TypeSafe AI の API キー。キーが未設定でも記録・検索およびローカルGUI判定は動作します。
- （任意）GUI 判定（System One）に Cloudflare Workers AI の Clef を使う場合は `cf auth login` 済みであること。`MCA_SYSTEM_ONE=clef` を指定したときだけ使います（詳細は下記）。

## ビルド手順

```bash
./Scripts/bundle.sh
open build/MyComputerAgent.app
```

アプリケーションバンドルの作成（bundle.sh）は必須です。macOS は署名済みバンドル識別子に対して権限を付与し、`Info.plist` から許可ダイアログの文面を読み込みます。未署名のバイナリでは `AudioHardwareCreateProcessTap` が**ダイアログを表示することなく即座に失敗**し、アプリのバグのように見えてしまいます。

配布用ビルドの場合は、Developer ID 署名を指定します：`./Scripts/bundle.sh "Developer ID Application: …"`。

### 実行中アプリへの変更の反映

```bash
# クイック再起動（現在起動中のインスタンスを終了し、再ビルドした .app を起動）
./Scripts/bundle.sh && killall MyComputerAgent 2>/dev/null; open build/MyComputerAgent.app
```

`swift build` の後に `open` を実行する方法は推奨されません（次の2つの理由により何も起こりません）：

- `swift build` は `.build/<config>/mca` を出力するのみです。これを `build/MyComputerAgent.app` に反映するのは `Scripts/bundle.sh` だけであり、品質ゲートではバンドルを生成しないため、コードを変更しても最後にバンドルされた古いバイナリが実行され続けます。
- 本アプリは `LSUIElement`（メニューバー常駐型）です。常駐型アプリに対する `open` は「再起動」ではなく「再表示（reopen）」扱いとなり、`applicationShouldHandleReopen` が呼ばれて設定ウィンドウが表示されるだけで、古いプロセスが居座り続けます。そのため事前にプロセスを終了する必要があります。

## 初回セットアップ

アプリを起動後、✨ メニューバーアイコン ▸ **Settings…（設定…）** からセットアップを行います。以下の2つの設定は必ず起動中のアプリ内から行う必要があり、ターミナル経由では正常に動作しません：

1. **アクセス権限** — アクセシビリティ、画面収録、マイク、音声キャプチャ。
   macOS は権限許可ダイアログを要求したプロセスに権限を紐付けます。ターミナルから `mca doctor` などを実行して許可すると、権限が Terminal.app に付与されてしまい、アプリ本体には権限が付かない状態になります。また、macOS がダイアログを出すのはアプリ識別子あたり1回のみです。以降は「システム設定 ▸ プライバシーとセキュリティ」から設定する必要があり、アプリの権限タブから該当設定画面へのディープリンクが用意され、トグル変更もリアルタイムに反映されます。
2. **モデルとAPIキー** — GeminiのAPIキーを貼り付けます。キーは後述の通り暗号化されて保存され、アプリ自身がキーチェーン項目を所有するため、「アクセスを許可しますか？」ダイアログなしで読み戻せます。キーの追加は即座に有効化され、再起動は不要です。

`mca auth set gemini` コマンドも利用可能ですが、その場合キーチェーン項目はCLIバイナリに属することになり、アプリ初回読み込み時にmacOSの許可ダイアログが挟まれます（バックグラウンド動作のエージェントからは見落としやすく、キー未設定と見分けがつきにくくなります）。

### APIキーの保存方法

キーチェーン内に平文で保存されることはありません。各APIキーは、**このMacのSecure Enclave内部で生成されたP-256鍵**を用いて **HPKE**（RFC 9180, `P256_SHA256_AES_GCM_256`）で封印（暗号化）され、暗号文のみがログインキーチェーンに保存されます。

キーチェーン自体もログインパスワードで暗号化されますが、`login.keychain-db` ファイルとパスワードが漏洩した場合に復号されてしまいます。一方、Secure Enclaveの秘密鍵はチップ外に一切出ず、パスワードから導出されたものでもなく、エクスポートも不可能なため、攻撃者がパスワードを知っていたとしても他のMac上では暗号文は無意味なデータとなります。プロバイダ名は追加認証データ（AAD）としてバインドされているため、あるプロバイダの暗号化データを別のプロバイダのスロットに偽装して移動することもできません。

運用上の重要な留意点：

- **旧ビルドで保存された平文キーは自動移行されます**：初回読み出し時に旧キーを取得した後、Secure Enclave経由で再封印して上書き保存します。ユーザー側の作業は不要です。
- **Macの初期化やSecure Enclaveのリセットを行うと、保存されたキーは読み取り不能になります**：意図的にデバイス固有にバインドされているためです。その場合は「設定」から再度キーを入力してください（アプリは「キーなし」ではなく再入力案内を表示します）。

Appleの新しいデータ保護キーチェーン（`kSecUseDataProtectionKeychain`）はあえて使用していません。プロビジョニングプロファイルが必要な `com.apple.application-identifier` / `keychain-access-groups` エンタイトルメントに依存しているためです。本アプリはあえてサンドボックスを外しプロファイルを持たない設計としているため、`SecItemAdd` は `-34018 errSecMissingEntitlement` を返してしまいます。CryptoKitのSecure Enclave鍵にはこのような制約はなく、鍵自体はキーチェーンではなくアプリがラッピングされた不透明なBlobとして自前で永続化します。

Secure Enclaveを持たないMac（Intel Mac等）では、ソフトウェアラッピング鍵に自動フォールバックし、設定画面にオレンジ色の警告を表示して、存在しないハードウェア保護を騙ることがないようにしています。

アプリを再署名するとバイナリIDが変わるため、再ビルドしたアプリは新規アプリとして認識され、再度権限を求められます。アドホック署名ではなく本物の証明書で署名することでこれを回避できます（`Scripts/bundle.sh` が自動検出します）。

```bash
build/MyComputerAgent.app/Contents/MacOS/mca doctor   # 読み取り専用でステータスを確認
```

### GUI 判定のモデル（System One）

画面操作の次の一手と、依頼を操作として扱うかの判定は、次の順で選ばれます。

1. `MCA_SYSTEM_ONE` を指定していればそのモデル
2. TypeSafe AI のキーがあれば TypeSafe Jev
3. なければ、ローカルの決定論的な判定

Cloudflare Workers AI の Clef（`@cf/cloudflare/clef`）は、`cf auth login` 済みでも自動では選ばれません。
使うときは `MCA_SYSTEM_ONE=clef`（軽量版は `clef-flash`）を指定してください。

Clef の token は `cf auth whoami` や `cf` プロファイルから取り、メモリにだけ保持します（リポジトリやキーチェーンには書きません）。
`CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID` があればそちらを優先します。
テキストだけでは確信が足りないとき（AX の候補が取れない、確信度が閾値未満）に限り、
長辺 768px に縮めたスクリーンショットを添えてもう一度判定します。これには画面収録の権限が必要です。

**送信されるデータ**：Clef を使う間は、依頼文・前面のアプリ名・画面の AX 候補（ラベルと座標）が Cloudflare に送られます。
再判定のときはディスプレイ全体のスクリーンショット（長辺 768px）も送られます。
cf の認証に失敗すると、5 分間はローカル判定で動き、その後もう一度試します。

| 環境変数 | 意味 |
|---|---|
| `MCA_SYSTEM_ONE` | `typesafe` / `clef` / `clef-flash` / `offline` で固定する（未指定・それ以外の値は TypeSafe キー → ローカル判定） |

## チャットウィンドウ

`⌥Space`、各画面の **Chat** ボタン、または ✨ ▸ **Open the Chat…** から開きます。画面中央最前面に開き、テキストフィールドに即座にキャレットが当たります。

意図的にモーダルウィンドウ（`NSApp.runModal`）にはしていません。モーダルにすると画面が薄暗くなり「必ず今答えなければならない」圧迫感を与えるだけでなく、メインアクター上で動作するプロアクティブスキャン、画面見守り、メニューバー、グローバルショートカットなどの実行ループがすべて停止してしまい、質問したい対象の作業ウィンドウの操作すら阻害してしまうためです。Escapeキーで閉じることができ、背後の作業はそのまま継続できます。

- **画面を見守る (Watch my screen)** — 既定はオフ。有効にすると、指定インターバル（15秒 / 45秒 / 2分）ごとにアクティブウィンドウを監視し、ミス、エラー、リスク、またはより良い手順を見つけた時だけ発言します。スレッド直下のステータス行に最終動作が表示されるため、「静かに見守っている」のか「故障している」のかを一目で判別できます。
- **見守り対象の選択 (📌)** — 後述の画面セレクターを開きます：アクティブウィンドウに追従、特定のウィンドウをピン留め、または特定のディスプレイ全体をピン留め。ピン留めされた対象は重なり順に関係なく監視されるため、別のアプリで作業しながら裏で進むビルドの完了を見守り続けることができます。また、チャットウィンドウを開いて質問しても追従が外れることがありません。`⌥⌘W` を押せばセレクターを開かずに現在のウィンドウを即座にピン留めでき、もう一度押すと解除されます。
  
  ウィンドウとディスプレイでは固定の意味合いが異なります。「ウィンドウのピン留め」はウィンドウをどこにドラッグしてもその中身を追従し、「ディスプレイのピン留め」は画面の一区画を固定してその領域に出入りするあらゆるものを監視します（タイピングしていない側のサブモニター全体を監視したい場合に最適です）。
- **解説 (Explain)** — 同じ仕組みのワンショット版です。現在選択されている対象をキャプチャしてその場で解説します。何もピン留めされていない場合はマウスポインタがあるディスプレイを、ウィンドウがピン留めされている場合はそのウィンドウを対象とします。画像で処理するため、アクセシビリティツリーが存在しないCanvas描画アプリ（作図ツール、PDF、ビデオ会議画面など）でも正確に動作します。

前回のスキャンから変化がない画面、除外リストに登録されたアプリ、本アプリ自身のウィンドウ、またはユーザーが要求した回答のストリーミング中には、一切リクエストを送信しません。3回連続で失敗した場合は監視を停止し、理由を表示します（APIキー抜けの状態で45秒ごとに無駄なリクエストを送り続けることはありません）。

ピン留めされた対象はテキストではなく画像で変化を比較します（非アクティブなウィンドウには読み取れるアクセシビリティツリーがないため）。そのため、変化がない場合はスクリーンショットとハッシュ計算のみで済み、OCRもモデルリクエストも発生しません。比較処理は意図的に粗く設計されており（32×32のグレースケールに縮小し8段階に量子化）、カーソルの点滅では変化と判定されず、ビルドの終了などの意味ある変化のみが検知されます。本アプリ自身のウィンドウや除外アプリのピン留めは拒否され、ピン留めされた対象が消失した場合（ウィンドウが閉じられた、モニターが抜かれた等）は、勝手に別の対象に移動することなく監視を安全に停止します。

ピン留め中は、作業デスク上を移動しても観察履歴は記録されません。フォーカス追従のキャプチャが停止するため、履歴の最新項目はピン留めされた作業対象のまま維持され、質問するまでの移動経路にあるウィンドウで上書きされることがありません。

ディスプレイ全体をピン留めする場合、特定アプリのスキップでは除外処理ができないため、キャプチャ内部で `SCContentFilter` を使用して除外アプリのウィンドウをフレーム合成から完全に排除します。パスワードマネージャーなどがピン留め画面上に置かれていても画像自体に含まれません。また、それらのウィンドウはセレクターの選択肢にも表示されません。

## 画面セレクター (Screen Picker)

画面共有ダイアログと同様の、リアルタイムサムネイルグリッド（ウィンドウ一覧およびディスプレイ一覧）を表示します。パネルやポップオーバーの **Screen** ボタン、チャットツールバーの 📌 ボタン、または ✨ ▸ **Choose a Screen to Watch…** から開きます。タイルをクリックして選択し、ダブルクリックまたは「**Watch this**」を押して適用。監視がオフだった場合は選択と同時に監視を開始します。

テキストのみのタイトル一覧とは異なり、サムネイルによって「複数のChromeウィンドウ」や「タイトルが途切れたターミナル」も視覚的に一瞬で判別できます。

サムネイルはセレクターが開いている間のみ3秒ごとに更新されます。閉じた後は完全に停止します。サムネイルは識別できれば十分なため、通常の見守りキャプチャよりも大幅に小さい解像度で軽量に撮影されます。

プレビューも本番キャプチャと同じプライバシーフィルターを通るため、除外アプリのタイルは表示されず、除外ウィンドウはディスプレイプレビューからも除外されます。また、セレクターウィンドウ自身も `sharingType = .none` に設定されているため、合わせ鏡のように無限ループしてキャプチャされる心配はありません。

## メニューバーアイコン

Dockアイコンは表示されず、メニューバーの ✨ ステータス項目がアプリの主たるインターフェイスとなります。

- **左クリック**: ステータス項目の直下にコパイロットパネルをポップオーバーとして開きます。カード一覧、質問入力欄、現在の障害情報が表示されます。外側をクリックすれば即座に閉じ、作業画面を塞ぎません。カードにホバーすると ✕ ボタンが表示され、個別Dismiss（非表示）が可能です（チャット履歴には保持されます）。
- **右クリック**（または ⌃+クリック）: コマンドメニューを開きます。

パネルが閉じている間に新しい助言カードが届くと未読バッジが表示され、エラーが発生したサブシステムはメニュー最上部に赤色で掲示されます。

- **Keep Overlay On Screen（常時オーバーレイ表示）** — 既定はオフ。オンにすると、ポップオーバーではなく画面隅の独立したフローティングウィンドウになります。
- **Float Above Other Windows（最前面表示）** — オフにすると、通常のウィンドウと同様に最前面アプリの背面に回ります。
- **Collapse to Pill（ピル型に最小化）** — タイトルバーのみの極小サイズに折りたたみます。
- **Click-Through（クリックスルー）** — 既定はオフ。オンにすると、ウィンドウレベルで `ignoresMouseEvents` が有効になり、オーバーレイ上のクリックがすべて背後のアプリに透過します。読取専用のHUDとして画面に置いておく場合に便利です。
- **Position（配置位置）** — 上下左右の四隅。ドラッグ移動にも対応し、移動後の位置が記憶されます。
- **Settings… / Permissions… / Quit Copilot**

## 言語と音声認識の設定

本アプリは、**英語・日本語・韓国語**の3言語を公式にフルサポートしています。**Settings ▸ General ▸ Language**（設定 ▸ 一般 ▸ 言語）から詳細にカスタマイズできます。

**Interface（表示言語）** — English、日本語、한국어、または *Match macOS*（macOSの設定に従う、デフォルト）。この設定1つで次の2つの動作が統一されます：

- UI全体の言語 — メニューバー、設定画面、オーバーレイ、権限ウォークスルー。
- AIが回答やアドバイスカードを生成する言語 — 翻訳APIを挟むのではなく、システムプロンプトの末尾に言語指定ディレクティブを直接付与するため、コードブロックが壊れることなく、追加のトークンコストも最小限に抑えられます。

**Engine（文字起こしエンジン）** — 音声入力と認識のバックエンドを選択：

- **Gemini Flash (Cloud / High Accuracy)**: GoogleのマルチモーダルAI「Gemini Flash」による高速バッチ認識。圧倒的な認識精度を誇り、日本語や韓国語に多い同音異義語の誤変換を文脈から正確に是正し、「あー」「えーと」などの不要なフィラーを自動で除去します。
- **macOS (On-Device / Private)**: Apple標準のオンデバイス `SpeechAnalyzer`。音声データがMacの外部に送信されることは一切なく、完全なオフラインプライバシーが保たれます。

**Speech（話す言語）** — マイク音声をどの言語として文字起こしするかを指定：*Automatic*（デフォルト）、English、日本語、한국어。UI言語と発話言語を分けるニーズ（UIは英語、発話は日本語など）に対応するため、インターフェイス言語とは独立して設定可能です。

*Automatic* は「UI言語に従う」という意味であり、「話された言語を自動判別する」という意味**ではありません**。`SpeechTranscriber` は単一のロケールに対して初期化されるため、リアルタイム自動判別を行うと複数の認識器を常時並行稼働させる必要があり、バッテリー消費が激しくコードスイッチング（言語の混在）にも弱いためです。そのため、実際に解決された言語はピッカー直下（例：`Automatic → 日本語 (ja-JP)`）、画面下部の大字幕、チャットのボイスバー、セッション開始カードなどに明示されます。また、設定画面には該当言語のオンデバイス認識モデルがインストール済みか、ダウンロード可能か、または未サポートかがリアルタイム表示されます。

両方を Automatic に設定した場合、音声ロケールは `Locale.current` に従います。変更はアプリの再起動なしで即座に適用されます。

なお、macOSやモデルプロバイダからの生のエラーメッセージ、および開発者向けの `mca` CLI コマンド体系は、検索性や標準性を保つため意図的に英語のまま提供されます。

## キーボードショートカット

既定値: `⌥Space` 質問 · `⌥⌘H` オーバーレイ表示切替 · `⌥⌘J` 最小化/展開 · `⌥⌘X` クリックスルー切替 · `⌥⌘V` 音声セッション · `⌥⌘W` このウィンドウをピン留め。

- `⌥Space`: オーバーレイの状態にかかわらず、チャットウィンドウを中央に開き入力欄にフォーカスを当てます。
- `⌥⌘W`: 現在アクティブなウィンドウをピン留めし、監視がオフだった場合は同時に開始します。通常のウィンドウを閉じるショートカット `⌘W` と競合しないよう設計されています。
- 音声モードは2つのボタンに分かれています：**ディクテーション（マイク）** と **Live会話（波形）**。押すと開始、再押下で終了、セッション中にもう一方を押すとスムーズに切り替わります。
- `⌥⌘V`: 直前に使用した音声モードを即座に開始/終了します。メニュー項目にも現在のモードのショートカットが表示されます。

すべてのショートカットは **Settings ▸ Shortcuts** から自由に変更可能です。他アプリとのキー競合の検知や重複防止、ショートカットの無効化にも対応しています。

## 発話内容の可視化フィードバック

音声入力はキーボードのようなタイピングの目視確認ができないため、聞き取った内容は以下の3箇所に同時に表示されます：

1. 作業中ディスプレイの最下部に大きく表示されるリアルタイム字幕
2. チャットウィンドウ上部のボイスバー
3. 発話終了後、チャットスレッド内に通常のユーザーメッセージとして自動挿入

確定済みの文字列と、エンジンが現在推測中の未確定文字列は、視覚的な不透明度（100% vs 50%）を変えて描画されます。ディクテーションモードでは認識言語タグも併記されるため、設定ミスによる誤認識もすぐに原因を特定できます。大字幕は **Settings ▸ General ▸ Voice** から非表示にすることも可能です。

## アーキテクチャ

7つの SwiftPM ターゲットで構成され、依存関係は厳格に単方向です：

```
mca (composition root)
 ├── MCAPresentation   NSPanel HUD, SwiftUI, グローバルホットキー
 ├── MCAInterop        MCP サーバー / クライアント
 ├── MCARealtime       Gemini Live 音声セッション, GeminiTranscriber (バッチ認識), WAVEncoder
 ├── MCAReasoning      プロバイダ抽象化, ルーティング, ツール実行, エージェント
 ├── MCAMemory         SQLite + FTS5 全文検索, ハイブリッド検索
 ├── MCAPerception     VAD (発話区間検出), オンデバイス STT, Vision OCR
 ├── MCASensing        ScreenCaptureKit, AXUIElement, CoreAudio タップ, VPIO
 └── MCACore           値型, ヘルスレジストリ, リングバッファ, 多言語ローカライゼーション
```

### 設計上の3大原則

1. **音声処理パスはプロセス境界を越えない**：CoreAudioのI/Oコールバックは、メモリ割り当てやロック、プロセス間通信（IPC）が禁止されているリアルタイムスレッド上で動作します。そのため、PythonやNode等の外部サイドカーに依存せず、すべてのキャプチャと割り込み処理（< 100msのバージイン）をアプリ内プロセスで完結させています。
2. **LLM推論パスはネットワーク制約を前提とする**：クラウドモデルの初回トークン生成には300〜800msかかるため、このレイヤーは過度な最適化よりも拡張性とモジュール性を最優先に設計されています。
3. **常時監視はほぼゼロコストで動作する**：5秒ごとの画面スキャンをすべてクラウドモデルに送信すると莫大なAPI費用がかかります。オンデバイスモデルによる一次トリアージゲートを挟むことで、全体の約2%の重要イベントのみをクラウドにエスカレーションし、月額コストを劇的に削減します。

### マルチプロバイダ抽象化

Gemini、Anthropic、OpenAI互換（Ollama、LM Studio、vLLM、Groq、OpenRouter対応）、およびAppleオンデバイスモデルは、すべて共通の単一プロトコル（`LanguageModelExecuting`）を実装しています。

タスクごとの最適ルーティング：

| タスク | 使用モデル | 備考 |
|---|---|---|
| `triage` (一次判定) | Apple オンデバイス | 完全無料、常時ローカル実行 |
| `classify` (分類) | `gemini-3.8-flash` | `thinkingLevel: minimal` |
| `answer` / `vision` (回答・画像分析) | `gemini-3.8-flash` | 標準推論 |
| `hardReasoning` (高度な推論) | `gemini-3.8-flash` | 明示的な要求時のみ、`thinkingLevel: high` |

モデルIDとトークン予算は `~/Library/Application Support/MyComputerAgent/config.json` に外部化されており、コードを再コンパイルすることなく柔軟に変更できます。

### セキュリティとプライバシー保護 (Security & Privacy)

MyComputerAgent は、徹底した**ゼロトラスト・ローカルファースト（Zero-Trust, Local-First）**アーキテクチャに基づいて設計されています。詳細なセキュリティポリシーおよび脆弱性報告窓口については [SECURITY.md](SECURITY.md) をご覧ください。

- **ハードウェア暗号化による安全な秘密情報保護**: 設定画面で登録された API キーは、Apple Silicon の **Secure Enclave（SEP）** 内で生成された P-256 キーに **HPKE（RFC 9180, `P256_SHA256_AES_GCM_256`）** で暗号化（シール）されます。平文のキーがディスクや平文キーチェーンに保存されることはありません。
- **パスワード管理アプリの事前完全除外**: 1Password、Bitwarden、Keychain Access、LastPass、KeePassXC などのパスワード管理ウィンドウは、キャプチャおよびアクセシビリティ検査の対象から完全に事前除外され、メモリやディスクに一切残りません。
- **保護フィールドの保護**: `AXSecureTextField`（パスワード入力欄や秘密文字列）の内容は絶対に読み取りません。
- **インフライト個人情報・秘密情報マスキング**: モデルへ送信されるすべての UI 要素テキストは正規表現サニタイザーを通過し、API キー、トークン、クレジットカード番号などが自動的にマスキングされます。
- **自己監視・自己キャプチャの防止**: 自プロセスの PID およびウィンドウ（HUD、チャットウィンドウ）は `sharingType = .none` に設定されており、画面操作や OCR による自身の再帰的監視・誤推論ループを防止します。
- **起動時マイク完全オフ**: アプリ起動時はマイクは一切開かれません。明示的な音声会話（⌥⌘V）の開始時にのみ開き、セッション終了と同時に即時クローズされます。
- **標準入出力（stdio）完結の MCP サーバー**: 外部エージェント連携（Claude Code、Codex 等）用 MCP サーバーはローカルの標準入出力でのみ動作し、ネットワークポートを外部に開放しません。

## テスト

```bash
swift test
```

**全48スイート、354件**のテストを収録：

- **Executor コントラクトテスト**: 偽装モックと実機プロバイダ（Gemini、Anthropic、Apple）が同一の検証基準を満たしているかを検証。
- **ワイヤーフォーマット検証**: 各プロバイダのリクエストペイロード（GeminiのthinkingLevel、Anthropicのtool_use、OpenAI形式など）を厳密にチェック。
- **実ファイルでのSQLite検証**: インメモリではなく実ファイルを用いてFTS5トリガーと検索を検証。
- **並行処理検証**: 音声リングバッファにおいて10万フレームの並行読み書きテストを実施。
- **発話区間・意図認識テスト**: ディクテーション境界判定ロジック（`DictationBuffer`）の境界値テスト。
- **GUI 自動化とグラウンディング検証**: AccessibilityInspector による自己プロセス除外、TypeSafe Jev 意思決定エンジンとローカル意味一致フォールバックの動作検証。

## 既知の制限事項

- ローカル一次トリアージゲートには Apple Intelligence の有効化が必要です。未有効の場合はクラウドモデルにフォールバックし、通信コストが増加します（`mca doctor` で状態を確認可能）。
- 話者分離はチャンネル単位（自分 vs 相手）です。リモート側の複数話者を分離するにはダイアライゼーションモデルが必要です。
- Live音声セッションの音声出力はデコードまで実装されており、オーディオ出力デバイスへの直接ルーティングは順次拡充予定です。
