## 1. 개요

MyComputerAgent(명령어 이름은 `mca`)는 macOS용 로컬 우선 데스크탑 코파일럿입니다. 작업 중인 윈도우의 내용을 읽고, 검색할 수 있는 기록을 사용자의 Mac 안에 보관하며, 화면에 보이는 내용에 관한 질문에 답하고, 실수나 더 빠른 방법을 발견하면 먼저 말을 건넵니다. 마이크와 시스템 오디오도 들을 수 있지만, 사용자가 요청했을 때만 듣습니다.

메뉴바(반짝이는 별 모양 아이콘)에 상주하며 Dock에는 아이콘이 나타나지 않습니다.

**요구 사항**

- Apple Silicon Mac에서 macOS 26 이상
- 소스에서 빌드하려면 Xcode 26.6 이상(Swift 6.2 이상)
- API 키는 선택 사항입니다. 키가 없어도 기록, 로컬 검색, 로컬 GUI 판정은 동작합니다. 클라우드 모델의 답변, 이미지 이해, 실시간 대화에는 키가 필요합니다([API 키](#5-api-키) 참조).

이 매뉴얼은 현재 앱이 실제로 하는 동작을 설명합니다. 설계 배경은 [README](../../README.ko.md), 보안 정책은 [SECURITY.md](../../SECURITY.md)를 참조하세요.

## 2. 설치와 빌드

미리 빌드된 설치 프로그램은 없습니다. 소스에서 앱 번들을 빌드합니다.

```bash
git clone https://github.com/buddypia/my-computer-agent.git
cd my-computer-agent
./Scripts/bundle.sh
open build/MyComputerAgent.app
```

`Scripts/bundle.sh`는 release 빌드를 만들고, `Info.plist`와 엔타이틀먼트를 넣어 `build/MyComputerAgent.app`으로 묶은 뒤 서명합니다.

**번들 생성 단계를 건너뛰지 마세요.** macOS는 서명된 번들 식별자(`com.buddypia.mca`)에 권한을 부여하고, 권한 안내 문구를 `Info.plist`에서 읽어 옵니다. `swift build`로 만든 단독 바이너리에는 둘 다 없습니다. 특히 서명되지 않은 바이너리에서는 `AudioHardwareCreateProcessTap`이 안내 창을 전혀 띄우지 않고 실패하므로 앱 버그처럼 보입니다.

### 서명

`bundle.sh`는 다음 순서로 서명 ID를 고릅니다. 첫 번째 인자로 넘긴 ID, 환경 변수 `MCA_SIGN_IDENTITY`, "Developer ID Application" 인증서, "Apple Development" 인증서, 마지막으로 ad-hoc 서명(`-`)입니다.

```bash
./Scripts/bundle.sh "Developer ID Application: Your Name (TEAMID)"
```

ad-hoc 서명은 바이너리 해시에 고정됩니다. 다시 빌드할 때마다 macOS에는 다른 앱으로 보이므로 권한을 다시 요청하고, 오래된 항목이 더 이상 맞지 않을 수 있습니다. 정식 인증서(Xcode ▸ Settings ▸ Accounts에서 만들 수 있는 무료 Apple Development 인증서면 충분합니다)로 서명하면 ID가 안정되어 이 문제를 피할 수 있습니다. ad-hoc 서명으로 다시 빌드한 뒤에는 `mca reset-permissions`를 실행하고 앱을 다시 실행하세요.

### 선택 사항: 응용 프로그램 폴더에 두기

`build/MyComputerAgent.app`을 `/Applications`에 복사해도 됩니다. 명령줄 도구는 번들 안에 있는 바이너리입니다([명령줄](#6-명령줄-mca) 참조).

### 개발 중 다시 빌드하기

```bash
./Scripts/run.sh
```

번들을 다시 빌드하고, 이전 프로세스를 종료한 뒤, 다시 실행합니다. `swift build` 후 `open`만 하면 변경 사항이 반영되지 않습니다. `swift build`는 번들을 갱신하지 않고, 이미 실행 중인 메뉴바 앱에 `open`을 하면 설정 윈도우만 다시 열리기 때문입니다.

## 3. 접근 권한

| 권한 | 앱이 필요로 하는 이유 | 없으면 |
|---|---|---|
| **손쉬운 사용** | 다른 앱 윈도우의 텍스트와 구조를 읽고, 동작을 위한 클릭과 키 입력을 보냅니다. | 에이전트는 아무것도 볼 수 없습니다. |
| **화면 기록** | OCR 대체, 화면 설명, 영역 선택, 화면 지켜보기, 화면 선택기 썸네일에 쓰는 스크린샷. | 손쉬운 사용 정보를 제공하지 않는 앱에서 OCR 대체가 동작하지 않고, 선택기에 윈도우가 나타나지 않습니다. |
| **마이크** | 음성 입력과 실시간 대화. | 사용자의 목소리를 듣지 못합니다. 통화 상대 쪽만 문자로 변환됩니다. |
| **오디오 기록** | CoreAudio 프로세스 탭으로 시스템 오디오를 가져옵니다(가상 오디오 드라이버가 필요 없습니다). | 회의 참가자의 음성을 듣지 못합니다. |

시스템 설정 ▸ 개인정보 보호 및 보안에서 화면 기록과 오디오 기록은 같은 "**화면 및 시스템 오디오 기록**" 항목에 있습니다. 마이크 권한이 필요한 것은 음성 세션을 시작할 때뿐입니다.

### 터미널이 아니라 실행 중인 앱에서 허용하세요

macOS는 권한을 "책임 프로세스"에 부여합니다. 터미널에서 실행한 바이너리라면 그것은 터미널입니다. 따라서 `mca doctor`에서 뜬 대화상자에 답하면 권한은 Terminal에 부여되고, 에이전트 앱에는 아무것도 남지 않습니다.

1. `open build/MyComputerAgent.app`으로 앱을 실행합니다(더블 클릭해도 됩니다).
2. 메뉴바의 별 모양 아이콘을 오른쪽 클릭해 **접근 권한…**을 선택합니다(설정의 접근 권한 탭이 열립니다).
3. **macOS에 전부 요청하기**를 누릅니다. macOS가 대화상자를 띄우는 것은 앱 식별자당 한 번뿐입니다. 이후에는 접근 권한 탭의 버튼으로 시스템 설정의 해당 항목으로 이동하세요. 스위치를 바꿀 때마다 탭의 표시가 갱신됩니다(**지금 다시 확인**으로 강제 갱신할 수 있습니다).
4. macOS가 재실행이 필요하다고 안내하면, 메뉴의 **Copilot 종료**로 앱을 종료한 뒤 다시 엽니다.

"My Computer Agent"는 앱이 한 번 권한을 요청한 뒤에야 화면 기록, 마이크, 오디오 기록 목록에 나타납니다. 목록에 없으면 앱이 실행 중인지 확인하고, 접근 권한 탭에서 다시 요청하세요.

접근 권한 탭은 각 항목을 **허용됨**, **허용되지 않음**, "이 앱이 아니라 터미널에 부여되어 있습니다" 중 하나로 표시합니다. 터미널에서 실행했거나 ad-hoc 서명 또는 서명 없음 상태이면 경고도 표시합니다.

`mca reset-permissions`는 `tccutil`로 이 앱의 마이크, 화면 기록, 손쉬운 사용, 음성 인식 권한을 초기화하여 macOS가 다시 대화상자를 띄우게 합니다.

## 4. 처음 실행

1. `MyComputerAgent.app`을 엽니다. Dock에 아이콘도 윈도우도 나타나지 않지만 메뉴바에 별 모양 아이콘이 생깁니다. 실행할 때 앱은 권한을 확인하고, 부족한 것이 있으면 대화상자를 띄웁니다.
2. 별 모양 아이콘을 오른쪽 클릭해 **설정…**을 선택합니다(앱을 한 번 더 열어도 설정이 열립니다).
3. **접근 권한** 탭: 위에서 설명한 대로 네 가지 권한을 허용합니다.
4. **모델과 키** 탭: Gemini 키를 붙여넣고 **저장**을 누릅니다(선택 사항이지만 권장합니다. [API 키](#5-api-키) 참조). 재실행 없이 바로 적용됩니다.
5. `⌥Space`를 눌러 채팅을 열고 화면에 보이는 내용에 관해 질문해 보세요.
6. 터미널에서 확인(선택 사항): `build/MyComputerAgent.app/Contents/MacOS/mca doctor`

실행 직후에는 듣거나 화면 이미지를 보내는 기능이 아무것도 켜져 있지 않습니다. 마이크는 닫혀 있고 **화면 지켜보기**는 꺼져 있습니다. 자세한 내용은 [개인정보 보호 방식](#13-개인정보-보호-방식)을 참조하세요.

## 5. API 키

키는 선택 사항입니다. 어떤 기능에 어떤 키가 필요한지는 다음과 같습니다.

| 프로바이더 | 설정상의 이름(id) | 환경 변수 | 역할 |
|---|---|---|---|
| Google Gemini | `gemini` | `GEMINI_API_KEY`(또는 `GOOGLE_API_KEY`) | 분류, 답변, 이미지 이해, 고난도 추론의 주 경로, 실시간 대화, Gemini Flash 음성 인식. |
| Anthropic | `anthropic` | `ANTHROPIC_API_KEY` | 답변과 이미지 이해의 대체 경로. |
| OpenAI 호환 | `openai-compatible` | `OPENAI_API_KEY` | 답변과 이미지 이해의 대체 경로(접속 대상은 `https://api.openai.com/v1`). |
| TypeSafe AI (Jev) | `typesafe` | `TYPESAFE_API_KEY` | 조작을 위한 저지연 GUI 판정. 키가 없으면 로컬의 결정론적 의미 매칭으로 대체합니다. |

기본 라우팅은 "끼어들 가치가 있는가"를 1차 판정하는 데 Apple 온디바이스 모델을 쓰고, 분류·답변·이미지 이해·고난도 추론에는 `gemini-3.8-flash`를 씁니다. 답변과 이미지 이해의 대체 경로는 Anthropic과 OpenAI 호환 모델입니다. `mca doctor`는 라우팅 표를 출력하고, 실행할 수 없는 경로에 표시를 붙입니다.

### 키 추가(권장 방법)

설정 ▸ **모델과 키** ▸ **API 키**에서 키를 붙여넣고 **저장**을 누릅니다. 키체인 항목을 앱이 직접 기록하므로, 나중에 읽을 때 "접근을 허용하겠습니까?" 대화상자가 뜨지 않습니다. 저장된 키는 다시 표시되지 않으며, **교체**하거나 **삭제**할 수 있습니다. 각 프로바이더에는 키의 출처가 "키체인에 저장됨", "$변수명 에서 가져옴", "키 없음" 중 하나로 표시됩니다.

### 키 저장 방식(`SecretStore`)

키는 평문으로 저장되지 않습니다. 각 키는 이 Mac의 Secure Enclave 안에서 생성한 P-256 키로 HPKE(RFC 9180, `P256_SHA256_AES_GCM_256`) 봉인되고, 암호문만 로그인 키체인에 들어갑니다. 프로바이더 이름이 인증된 추가 데이터로 묶여 있어 한 프로바이더의 항목을 다른 프로바이더 슬롯으로 옮길 수 없습니다.

- 이전 빌드에서 저장된 키는 처음 읽을 때 자동으로 다시 봉인됩니다.
- Mac을 초기화하거나 Secure Enclave를 리셋하면 저장된 키를 읽을 수 없게 됩니다(의도적으로 기기에 묶여 있기 때문입니다). 키를 다시 붙여넣으세요. 앱은 "키 없음" 대신 그 사실을 알려 줍니다.
- Secure Enclave가 없는 Mac에서는 소프트웨어 키로 감싸며, 설정 화면에 주황색으로 그 사실이 표시됩니다.

### 환경 변수

환경 변수에 비어 있지 않은 값이 설정되어 있으면 키체인보다 우선하며, 어디에도 기록되지 않습니다. 개발할 때나 셸에서 실행하는 `mca` 명령에 유용합니다.

- Finder나 `open`으로 실행한 메뉴바 앱은 셸 프로파일의 환경 변수를 **물려받지 않습니다**. 앱에는 설정 화면을, 터미널에서 실행하는 명령(MCP 클라이언트가 실행하는 `mca mcp` 포함)에는 환경 변수를 쓰세요.
- 앱은 `.env` 파일을 읽지 않습니다. 저장소의 `.env.example`은 변수 이름 목록일 뿐입니다. 셸이나 MCP 클라이언트 설정에서 지정하세요.

### 명령줄

```bash
mca auth set gemini        # 표준 입력으로 받으므로 셸 히스토리에 키가 남지 않습니다
mca auth delete gemini
```

프로바이더는 `gemini`, `anthropic`, `openai-compatible`, `typesafe`입니다. CLI로 저장한 키는 CLI 바이너리의 소유가 되므로 앱이 처음 읽을 때 macOS가 허용을 요청합니다. 알아차리기 어렵고 "키 없음"과 구별되지 않습니다. 설정 화면에서 추가하는 것을 권장합니다.

## 6. 명령줄 mca

실행 파일은 앱 번들 안에 있습니다. 별칭을 만들어 두면 편리합니다.

```bash
alias mca="/path/to/MyComputerAgent.app/Contents/MacOS/mca"
```

명령 없이 실행하면 앱이 시작됩니다(`mca run`). 명령 앞에 두는 전역 옵션으로 `--debug` 또는 `-d`가 있으며 자세한 로그를 켭니다(`MCA_DEBUG=1`과 같습니다).

| 명령 | 내용 |
|---|---|
| `mca run` | 코파일럿과 메뉴바 아이콘을 시작합니다(기본값). |
| `mca doctor` | 읽기 전용 리포트. 권한, 코드 서명, Apple Intelligence 사용 가능 여부, 어떤 프로바이더의 키가 있는지, 기록 데이터베이스 경로와 저장된 건수, 라우팅을 출력합니다. |
| `mca listen [초]` | 지정한 시간(기본 20초) 동안 캡처하여 문자로 변환하고, 마이크와 시스템 오디오 두 채널을 따로 출력합니다. |
| `mca capture [초]` | 지정한 시간(기본 0초)을 기다린 뒤 활성 윈도우를 한 번 읽어 추출한 내용을 출력합니다. 개인정보 보호 필터의 제외 대상이면 그렇다고 알려 줍니다. |
| `mca ask "질문"` | 현재 데스크탑 컨텍스트를 사용한 단발성 질문. 답변은 표준 출력으로 스트리밍됩니다. |
| `mca search "검색어"` | 기록된 히스토리를 검색합니다(온디바이스 쿼리 확장 포함). 최대 20건을 출력합니다. |
| `mca act …` | 화면 조작을 실행합니다(아래 참조). |
| `mca browser …` | 요소 참조를 사용해 Chromium 계열 브라우저를 조작합니다(아래 참조). |
| `mca mcp` | 표준 입출력으로 MCP 서버를 실행합니다([7장](#7-claude-code와-codex에서-쓰는-mcp)). |
| `mca auth set\|delete <provider>` | 프로바이더 API 키를 저장하거나 삭제합니다. |
| `mca setup` | 권한 설정 마법사를 엽니다(실행 중인 앱의 설정 ▸ 접근 권한을 권장). |
| `mca reset-permissions` | 이 앱의 TCC 권한을 초기화하여 macOS가 다시 대화상자를 띄우게 합니다. |
| `mca help` | 사용법을 출력합니다. |

터미널에서 실행하는 명령(`doctor`, `listen`, `capture`, `ask`, `act`)이 보여 주는 것은 앱이 아니라 **터미널**의 권한입니다. `mca doctor`는 이를 감지하면 경고를 출력합니다.

### `mca act`

```text
mca act [options] [<goal>]
  --goal, -g <text>        자연어 목표(--autonomous를 포함합니다)
  --autonomous, -a         하위 목표를 세우고 완료될 때까지 반복합니다
  --max-steps, -s <n>      최대 단계 수(기본 20)
  --confidence, -c <0-1>   최소 확신도(기본 0.80)
  --dry-run, -n            클릭이나 키 입력은 보내지 않고 계획과 판단만 합니다
```

```bash
mca act "검색 버튼 클릭"                                              # 1단계
mca act --goal "Safari를 열어 도쿄 날씨 검색" --dry-run              # 미리보기만
mca act --autonomous --max-steps 15 "가입 양식 작성"
```

이 명령은 실제로 마우스를 움직이고 글자를 입력합니다. 먼저 `--dry-run`으로 시험해 보세요. 자율 실행은 Ctrl+C로 중단할 수 있습니다. `--dry-run` 없이 실행하려면 터미널에 손쉬운 사용 권한이 필요합니다.

### `mca browser`

DevTools 엔드포인트(`127.0.0.1`의 9222번과 9333번 포트를 차례로 시도)로 브라우저를 조작하고, 찾지 못하면 맨 앞 브라우저 윈도우에 대해 macOS 손쉬운 사용으로 대체합니다. 전용 탭을 열며 사용자의 탭은 조작하지 않습니다.

```text
navigate <url> | snapshot [--filter T] [--max-depth N] | click <ref> | fill <ref> <text>
type [<ref>] <text> | press <key> | select <ref> <option> | scroll <ref> <percent>
act "<instruction>" | observe ["<instruction>"] | extract "<instruction>"   (모델이 필요합니다)
text | url | title | tabs | tab new|switch|close | wait … | eval "<js>" | screenshot [path]
back | forward | reload
```

전체 목록은 `mca browser help`로 확인할 수 있습니다.

## 7. Claude Code와 Codex에서 쓰는 MCP

`mca mcp`는 **표준 입출력**으로 Model Context Protocol 서버를 실행합니다. 네트워크 포트는 열지 않습니다. 클라이언트가 하위 프로세스로 실행합니다.

**제공되는 도구**

| 도구 | 용도 |
|---|---|
| `search_context` | 사용자가 보고 들은 것을 검색합니다(검색어, 최근 N분, 앱, 건수). |
| `recent_activity` | 사용자가 최근에 하던 일. |
| `conversation_history` | 최근 대화의 문자 기록(`me`, `others`, `all`). |
| `computer` | 좌표를 지정한 마우스와 키보드 조작. |
| `click_element` | 제목이나 레이블로 UI 요소를 클릭합니다. |
| `run_applescript` | AppleScript를 실행합니다. |
| `inspect_ui_elements` | 활성 윈도우의 조작 가능한 요소를 나열합니다. |
| `typesafe_act` | 자연어 목표로 GUI 조작을 한 번 수행합니다. |
| `autonomous_act` | 단계 상한, 확신도 임계값, 드라이런을 지정할 수 있는 여러 단계의 목표 실행. |
| `browser_*` | 브라우저 조작 도구(navigate, snapshot, element, act, observe, extract, read, tabs, wait, evaluate). `config.json`에서 브라우저 자동화를 끄지 않았다면 포함됩니다. |

**Claude Code**

```bash
claude mcp add my-computer-agent -- /path/to/MyComputerAgent.app/Contents/MacOS/mca mcp
```

**Codex CLI**(`~/.codex/config.toml`)

```toml
[mcp_servers.my-computer-agent]
command = "/path/to/MyComputerAgent.app/Contents/MacOS/mca"
args = ["mcp"]
```

참고 사항:

- 서버는 앱과 같은 기록 데이터베이스를 읽습니다. 검색할 내용이 있도록 앱을 먼저 실행해 두세요(과거에 실행한 적이 있으면 됩니다).
- 권한은 서버를 실행한 프로그램(터미널이나 편집기)에 부여됩니다. 컴퓨터 조작 도구에는 그 프로그램의 손쉬운 사용 권한이 필요합니다. 기록 검색에는 별도 권한이 필요 없습니다.
- **위험한 도구는 MCP를 통하면 기본적으로 거부됩니다.** MCP 클라이언트에는 사용자에게 확인을 보여 줄 방법이 없으므로 `run_applescript`, `computer`, `click_element`, `typesafe_act`, `autonomous_act`(드라이런이 아닐 때), 페이지를 조작하는 브라우저 도구(`browser_navigate`, `browser_element`, `browser_act`, 탭을 열거나 전환하거나 닫는 `browser_tabs`, `path`를 지정한 `browser_read`), 그리고 `browser_evaluate`는 오류를 반환합니다. 읽기 도구(검색, 기록, `inspect_ui_elements`, `browser_snapshot`, `browser_observe`, `browser_extract`, `browser_wait`, 읽기 용도의 `browser_read`와 `browser_tabs`)는 그대로 동작합니다. 신뢰하는 클라이언트에 한해 허용하려면 `config.json`에 `"mcpAllowDangerousTools": true`를 설정하고 클라이언트를 다시 시작하세요. 자세한 내용은 [SECURITY.ko.md](../../SECURITY.ko.md) 5항을 참조하세요.
- `computer`, `click_element`, `run_applescript`, act 계열 도구는 연결된 에이전트가 사용자의 Mac을 조작하게 합니다. 신뢰할 수 있는 클라이언트만 연결하고, 시험할 때는 `dry_run`을 사용하세요.
- 프로바이더 키는 앱과 같은 순서로 확인합니다. 먼저 환경 변수(예: `GEMINI_API_KEY`, 클라이언트의 환경에서 물려받음), 그다음 키체인입니다.

## 8. 메뉴바 아이콘과 패널

별 모양 아이콘이 앱의 본체입니다.

- **왼쪽 클릭**: 코파일럿 패널이 팝오버로 열립니다. 카드, 질문 입력란, 문제가 있는 부분이 표시됩니다. 다른 곳을 클릭하면 닫힙니다. 카드 위에 커서를 올리면 ✕가 나타나 카드를 지울 수 있습니다(같은 내용은 채팅에 남습니다).
- **오른쪽 클릭**(또는 Control을 누른 채 클릭): 메뉴가 열립니다.
- 패널이 닫혀 있는 동안 카드가 도착하면 아이콘에 건수가 표시됩니다. 클릭 통과가 켜져 있는 동안에는 아이콘이 사선이 그어진 커서 모양으로 바뀝니다. 툴팁에는 현재 상태가 나옵니다. 문제가 생긴 서브시스템은 메뉴 맨 위에 경고 표시와 함께 나옵니다.

**메뉴 항목**

| 항목 | 내용 |
|---|---|
| 데스크탑에 패널 표시 | 꺼짐(기본값)이면 패널은 팝오버입니다. 켜면 화면 모서리에 떠 있는 윈도우가 됩니다. |
| 얇은 바로 접기 / 패널을 원래 크기로 | 떠 있는 패널을 얇은 제목 표시줄만 남기고 줄입니다. |
| 항상 맨 앞에 표시 | 켜면 모든 Space와 전체 화면 앱 위에서도 맨 앞에 남습니다. 끄면 일반 윈도우처럼 동작합니다. |
| 클릭을 뒤로 통과시키기 | 켜면 패널 자체의 버튼을 향한 클릭을 포함해 패널에 대한 모든 클릭이 뒤쪽 앱으로 전달됩니다. `⌥⌘X`나 이 메뉴로 끌 수 있습니다. |
| 표시 위치 | 위 또는 아래, 왼쪽 또는 오른쪽. 클릭 통과가 꺼져 있으면 패널을 드래그해 옮길 수도 있으며, 옮긴 위치가 기억됩니다. |
| 채팅 열기… | 채팅 윈도우를 엽니다(`⌥Space`). |
| 화면 영역 선택하여 설명… | 화면의 일부를 드래그해 선택하고 설명을 요청합니다. Esc로 취소합니다. |
| 채팅 지우기… | 확인 후 모든 메시지를 삭제합니다. |
| 지켜볼 화면 고르기… | 화면 선택기를 엽니다. 지켜보는 대상이 있으면 항목 이름에 그 대상이 표시됩니다. |
| 실시간 대화 시작 / 음성 입력 시작 | 두 가지 음성 모드([11장](#11-음성과-언어-설정)). |
| 설정… | 메뉴가 열려 있는 동안에는 `⌘,`. |
| 접근 권한… | 설정 ▸ 접근 권한을 엽니다. |
| Copilot 종료 | 메뉴가 열려 있는 동안에는 `⌘Q`. |

윈도우 관련 항목(접기, 맨 앞, 클릭 통과, 표시 위치)은 떠 있는 패널에 적용되며, 패널이 꺼져 있는 동안에는 흐리게 표시됩니다. 이 선택들은 모두 다음 실행 때도 유지됩니다. 설정 ▸ **패널**에도 같은 스위치가 있으며, 추가로 **스크린샷에 패널이 찍히도록 허용**(기본값 꺼짐, [개인정보 보호 방식](#13-개인정보-보호-방식) 참조)이 있습니다.

## 9. 채팅 윈도우

`⌥Space`, 패널의 **채팅** 버튼, 또는 메뉴의 **채팅 열기…**로 엽니다. 화면 중앙 맨 앞에 열리며 입력란에 이미 커서가 놓여 있습니다. 의도적으로 모달로 만들지 않았으므로 다른 작업은 그대로 계속할 수 있습니다. Esc로 닫습니다.

답변과 에이전트가 스스로 알아챈 내용이 하나의 스레드에 모입니다. 전송은 Return입니다. 메시지를 오른쪽 클릭하면 **복사**, **이 메시지 지우기**, **여기까지 한꺼번에 지우기**를 고를 수 있습니다. 휴지통 아이콘(또는 메뉴의 **채팅 지우기…**)은 확인 후 새 대화를 시작합니다. 스레드는 세션 동안 메모리에 보관됩니다.

**툴바**

| 조작 | 내용 |
|---|---|
| **화면 설명** (Explain) | 단발성. 선택기가 가리키는 대상을 보고 채팅에서 설명합니다. 고정한 것이 없으면 포인터가 있는 디스플레이가 대상입니다. 이미지를 사용하므로 직접 그려지는 앱(다이어그램, PDF, 화상 회의)에서도 쓸 수 있습니다. |
| **영역 선택** (Snip) | 화면의 일부를 드래그해 선택하고 설명을 요청합니다. |
| **화면 지켜보기** (Continuous Watch) | 화면 지켜보기를 켜고 끕니다(다음 장). 동작 중에는 "보는 중" 또는 "확인 중…"으로 표시됩니다. |
| 핀 버튼 | 화면 선택기를 엽니다. 고정한 윈도우나 디스플레이, 또는 지켜보는 화면 수가 표시됩니다. |
| 간격 메뉴 | 화면을 보는 간격: 15초마다, 45초마다, 2분마다. |
| 마이크 | **음성 입력**(Dictation). |
| 파형 | **실시간 대화**(Live conversation). |
| 휴지통 | 새 대화를 시작합니다. |

입력란 옆에는 **프리셋** 막대("프리셋 실행:")가 있고 현재 대상이 표시됩니다. 프리셋은 현재 대상에 대해 한 번만 실행됩니다("지금 1회 실행"). 프리셋 메뉴에서 지속적인 지켜보기의 목적으로 설정하거나, 편집하거나, 삭제할 수도 있습니다.

## 10. 화면 지켜보기와 화면 선택기

### 화면 지켜보기(Continuous Watch)

기본값은 꺼짐이며, 실행할 때마다 꺼진 상태로 돌아갑니다. 켜면 에이전트가 일정 간격으로 대상을 살펴보고, 실수, 오류, 위험, 더 빠른 방법을 발견했을 때만 말합니다. 스레드 아래 줄에 마지막 동작이 표시되므로 조용히 지켜보는 중인지 고장 났는지 구분할 수 있습니다.

지난번 이후 변화가 없는 화면, 제외 목록에 있는 앱, 이 앱 자신의 윈도우, 그리고 요청한 답변이 스트리밍되는 동안에는 아무것도 보내지 않습니다. 연속 3회 실패하면 지켜보기를 멈추고 이유(예: API 키 없음)를 알려 줍니다.

고정한 대상은 작은 그레이스케일로 축소한 거친 이미지로 비교합니다. 그래서 깜빡이는 커서는 변화로 보지 않고 빌드 완료는 변화로 봅니다. 고정한 윈도우가 닫히거나 고정한 모니터가 분리되면 다른 곳으로 옮겨 가지 않고 지켜보기를 멈춥니다. 무언가를 고정해 두는 동안에는 포커스에 따른 캡처를 멈추므로, 고정한 대상이 기록에서 가장 최신 상태로 유지됩니다.

### 화면 선택기

채팅의 핀 버튼, 패널의 **화면** 버튼, 메뉴의 **지켜볼 화면 고르기…**로 엽니다. 라이브 썸네일(열려 있는 동안 3초마다 갱신)이 **윈도우**와 **화면 전체** 두 그룹으로 나열됩니다.

- 타일을 클릭해 선택합니다. 더블 클릭하거나 **이 화면 보기**(Return)를 누르면 적용됩니다. 적용하면 지켜보기가 꺼져 있었더라도 켜집니다. Esc나 **취소**로 닫습니다.
- **앞쪽 윈도우**는 맨 앞에 있는 윈도우를 따라갑니다. 고정한 **윈도우**는 어디로 드래그해도 그 내용을 계속 따라갑니다. 고정한 **디스플레이**는 책상의 한 영역을 붙잡고 그 위에 나타나는 것을 지켜봅니다.
- 타일 모서리의 동그란 버튼으로 여러 대상을 한꺼번에 고를 수 있으며, 이때 버튼은 "N개 화면 지켜보기 시작"이 됩니다. 대상마다 **목적** 메뉴가 있으며, 기본 제공 목적(범용 조언, 오류 진단, 요약·회의록, 할 일 추출, 코드 리뷰, 회의 지원, AI CLI 개발 모니터링, 사양·디자인 대조)과 **사용자 지정 목적 편집…**으로 직접 만드는 목적이 있습니다. 기본 제공 목적은 일본어로 작성되어 있습니다.
- 제외 대상 앱은 타일이 나타나지 않습니다. 제외 대상 윈도우는 디스플레이 타일과 전송 내용에서도 빠집니다. 선택기 자신의 윈도우는 화면 캡처에서 숨겨집니다.
- 목록이 비어 있다면 대개 화면 기록이 허용되지 않은 것입니다.

`⌥⌘W`는 선택기를 열지 않고 지금 작업 중인 윈도우를 고정합니다(지켜보기도 시작합니다). 다시 누르면 해제됩니다.

### 영역 선택(Snip)

**영역 선택**(채팅 툴바, 패널, 메뉴)을 고르면 화면이 어두워지고 사각형을 드래그해 선택할 수 있습니다. 선택한 영역이 모델로 전송되어 설명이 돌아옵니다. Esc로 취소합니다.

## 11. 음성과 언어 설정

### 두 가지 음성 버튼

- **음성 입력**(Dictation, 마이크): 말한 내용을 문자로 바꿔 타이핑한 질문과 같은 채팅 모델에 전달합니다. 화면 맥락과 도구도 그대로 쓸 수 있습니다. 음성이 Mac 밖으로 나가는지는 음성 인식 엔진(아래)에 따라 달라집니다.
- **실시간 대화**(Live conversation, 파형): Gemini가 하나의 연결로 음성을 듣고 음성으로 답합니다. 최신 정보가 필요하면 웹도 검색합니다. **대화가 열려 있는 동안 마이크 음성이 Google로 계속 전송됩니다.** Gemini 키가 필요합니다.

버튼을 누르면 시작, 다시 누르면 종료, 세션 중에 다른 쪽을 누르면 전환됩니다. `⌃⌥V`는 마지막으로 사용한 모드를 시작하고, 다시 누르면 종료합니다. 마이크가 들은 내용은 작업 중인 화면 하단에 큰 글자로 표시되고, 채팅의 음성 막대에도 나타나며, 턴이 끝나면 일반 사용자 메시지로 대화에 추가됩니다. 확정된 글자와 엔진의 잠정 추측은 농도를 달리해 그려집니다. 큰 자막은 설정 ▸ 일반 ▸ **음성 대화**에서 끌 수 있습니다.

실행 직후에는 마이크가 열려 있지 않습니다. 음성 세션을 시작하면 열리고 끝나면 닫힙니다. 마이크와 시스템 오디오 탭을 계속 열어 두려면 설정 ▸ 일반 ▸ **오디오 입력**의 **항상 마이크로 듣기**를 켜세요(기본값 꺼짐. 마이크 권한 요청이 뜨거나 음성 모델 다운로드가 시작될 수 있습니다).

### 언어(설정 ▸ 일반 ▸ 언어)

- **화면 표시**: English, 日本語, 한국어, 또는 **macOS 설정 따르기**(기본값). 메뉴, 설정, 권한 화면의 언어와 에이전트가 답변과 조언을 쓰는 언어가 이것으로 정해집니다. 즉시 반영됩니다.
- **인식 엔진**: **Gemini Flash (클라우드·고정밀)** 또는 **macOS (온디바이스·완전 로컬)**. 기본값은 Gemini Flash이며, 음성 인식을 위해 음성을 Gemini로 보냅니다. Gemini 키가 저장되어 있지 않으면 온디바이스 엔진을 사용합니다. 음성이 Mac 밖으로 나가면 안 된다면 **macOS (온디바이스·완전 로컬)**를 고르세요.
- **말하는 언어**: 자동(기본값), English, 日本語, 한국어. **자동은 화면 표시 언어를 따릅니다.** 말하고 있는 언어를 감지하는 것이 아닙니다. 설정에는 결정된 언어(예: "자동 → 한국어 (ko-KR)")와 그 언어의 온디바이스 모델이 설치되어 있는지, 다운로드 가능한지, 지원되지 않는지가 표시됩니다. 처음 음성 입력할 때 한동안 멈춰 있다면 대개 모델을 다운로드하는 중입니다. Mac이 해당 언어를 지원하지 않으면 음성 입력은 시작되지 않지만 실시간 대화는 사용할 수 있습니다.

말하는 언어를 바꾸면 음성 인식이 다시 시작되므로, 전환 전후 몇 초의 음성은 가져오지 못합니다. macOS와 모델 프로바이더가 돌려주는 오류 문구는 받은 그대로 원래 언어로 표시됩니다. `mca` 명령줄은 영어만 지원합니다.

## 12. 키보드 단축키

기본값(모두 전역 단축키이며 모두 변경할 수 있습니다):

| 단축키 | 동작 |
|---|---|
| `⌥Space` | 질문하기: 채팅을 열고 입력란에 커서를 놓습니다 |
| `⌥⌘H` | 패널 보기 / 가리기(에이전트는 계속 지켜봅니다) |
| `⌥⌘J` | 패널 접기 / 되돌리기 |
| `⌥⌘X` | 클릭을 뒤로 통과시키기(전환) |
| `⌃⌥V` | 음성 대화 시작 / 종료(마지막으로 사용한 모드) |
| `⌥⌘W` | 이 윈도우 지켜보기(고정, 다시 누르면 해제) |

그 밖의 키: `Esc`는 채팅 윈도우를 닫고 영역 선택과 화면 선택기를 취소합니다. `Return`은 메시지를 전송하고 선택기의 선택을 적용합니다. 메뉴바 메뉴가 열려 있는 동안에는 `⌘,`와 `⌘Q`를 쓸 수 있습니다. `⌘W`는 기존처럼 윈도우를 닫습니다. Option 키를 포함한 조합 전체가 등록되어 있기 때문입니다.

설정 ▸ **단축키**에서는 새 단축키 기록, 단축키 지우기(메뉴바로는 계속 조작할 수 있습니다), **기본값으로 되돌리기**를 할 수 있습니다. macOS는 전역 단축키를 가장 먼저 등록한 앱에 주고 다른 앱에는 아무것도 알리지 않습니다. 그래서 이 탭은 다른 앱이 쓰고 있는 단축키에 표시를 하고, 이미 다른 동작에 지정된 단축키는 거부하며, macOS가 텍스트 편집용으로 예약한 단축키(`⌘V` 등)도 거부합니다.

## 13. 개인정보 보호 방식

**실행 직후에는 꺼짐.** 마이크와 시스템 오디오 탭은 음성 세션을 시작하거나 "항상 마이크로 듣기"를 켤 때까지 닫혀 있습니다. 화면 이미지를 보내는 **화면 지켜보기**는 꺼져 있으며, 실행할 때마다 꺼진 상태에서 시작합니다.

**기본적으로 기록되는 것.** 손쉬운 사용이 허용되어 있으면 OS 이벤트(포커스 변경, 윈도우 제목 변경, 타이핑 멈춤)를 계기로 활성 윈도우의 텍스트를 읽습니다. 손쉬운 사용 정보를 제공하지 않는 앱에서는 온디바이스 OCR로 대체하며, 로컬 SQLite 데이터베이스에 저장합니다. 오디오를 캡처한 경우에는 말한 내용의 문자 기록도 저장됩니다. 30일이 지난 기록은 자동으로 삭제됩니다. 프레임 레이트로 주기적인 감시는 하지 않습니다.

**읽지 않는 것, 필터링되는 것**

- 제외 대상 앱과 윈도우. 기본적으로 다음 번들 ID는 아무것도 저장하기 전에 건너뜁니다: 1Password, Bitwarden, 키체인 접근, LastPass, Dashlane, Apple 암호. 윈도우 제목에 `private browsing`, `incognito`, `シークレット`, `password`, `パスワード`, `sign in`, `2fa`, `one-time code`가 들어 있는 것(대소문자 구분 없음)도 마찬가지로 건너뜁니다. 두 목록 모두 `config.json`에서 바꿀 수 있습니다([14장](#14-데이터-위치와-삭제-방법)).
- 암호 관리 앱(1Password, Bitwarden, Apple 키체인 접근과 암호, KeePassXC)에 대한 조작은 강제로 차단됩니다. 에이전트는 이 앱들의 내부를 살펴보거나 클릭하지 않습니다.
- 암호 입력란(`AXSecureTextField`)은 윈도우를 읽을 때 건너뛰고, 조작 도구가 보는 UI 요소에서도 제거됩니다.
- 조작 계열 처리에서는 UI 레이블과 값이 모델에 도달하기 전에 패턴 매칭으로 가려집니다. 대상은 API 키, Bearer 토큰, 시크릿처럼 보이는 문자열, `sk-…`, `ghp_…`, `AKIA…` 형식의 토큰, 16자리 카드 번호입니다.
- 고정한 디스플레이에서는 제외 대상 윈도우가 캡처 내부에서 제거되므로, 흐리게 처리되는 것이 아니라 이미지에 존재하지 않습니다.
- 이 앱 자신의 윈도우는 에이전트가 자기 답변을 다시 읽지 않도록 화면 캡처에서 숨겨져 있습니다. 떠 있는 패널은 **스크린샷에 패널이 찍히도록 허용**(기본값 꺼짐)으로 캡처에 보이게 할 수 있습니다.

**Mac 안에 남는 것과 밖으로 나갈 수 있는 것**

| 데이터 | 가는 곳 |
|---|---|
| 캡처한 윈도우 텍스트, OCR, 기록, 검색 인덱스 | Mac의 로컬 데이터베이스 안에 남습니다. |
| 온디바이스 "끼어들 가치가 있는가" 판정 | Apple 온디바이스 모델. 통과한 것만 클라우드 모델에 도달합니다. Apple Intelligence가 없으면 이 판정은 클라우드 모델로 대체됩니다. |
| 사용자가 하는 질문, 그 컨텍스트와 도구 결과 | 답변하는 모델 프로바이더로 전송됩니다(기본값은 Gemini, 다음으로 Anthropic이나 OpenAI 호환 대체 경로). |
| 화면 설명, 영역 선택, 화면 지켜보기에 쓰는 이미지 | 클라우드 이미지 이해 모델로 전송됩니다. |
| 음성 입력의 음성 | 온디바이스 엔진: Mac 안에 머물고 문자만 전송됩니다. Gemini Flash 엔진: 음성 인식을 위해 음성이 Gemini로 전송됩니다. |
| 실시간 대화의 음성 | 대화가 열려 있는 동안 Google로 스트리밍됩니다. |
| API 키 | Secure Enclave로 봉인되며 암호문만 로그인 키체인에 들어갑니다. |

클라우드와의 모든 통신은 TLS(HTTPS 또는 WSS)를 사용합니다. MCP 서버는 표준 입출력만 쓰며 수신 대기 포트를 열지 않습니다. 취약점 신고는 [SECURITY.md](../../SECURITY.md)를 참조하세요.

## 14. 데이터 위치와 삭제 방법

| 내용 | 위치 |
|---|---|
| 기록 데이터베이스(기록과 검색 인덱스) | `~/Library/Application Support/MyComputerAgent/context.sqlite3`(`-wal`, `-shm` 파일이 함께 생깁니다) |
| 선택 사항인 설정 파일 | `~/Library/Application Support/MyComputerAgent/config.json` |
| `mca browser` 상태 | `~/Library/Application Support/MyComputerAgent/browser-cli.json`(앱이 전용 Chrome을 실행한 경우에만 `chrome-profile/`도 생깁니다) |
| 패널, 단축키, 언어, 음성, 지켜보기 환경설정 | 환경설정 도메인 `com.buddypia.mca` |
| API 키(암호문)와 래핑용 항목 | 로그인 키체인. 서비스 이름은 `com.buddypia.mca.providers`와 `com.buddypia.mca.wrapping-key` |
| 권한 허용 상태 | macOS 개인정보 보호 데이터베이스(TCC). 시스템 설정 ▸ 개인정보 보호 및 보안에서 확인할 수 있습니다 |

`config.json`은 선택 사항이며 앱이 설정을 저장할 때 만들어집니다. 적지 않은 키는 기본값을 유지하고, 변경 사항은 다음 실행부터 반영됩니다. 주요 키는 `retentionDays`(기본 30), `excludedBundleIDs`(번들 ID 접두사 일치. 지정하면 기본 목록을 **대체**하므로 남기고 싶은 기본값은 직접 옮겨 적으세요), `excludedWindowPatterns`, `mcpAllowDangerousTools`(기본 `false`. `true`로 하면 MCP 클라이언트가 확인 없이 Mac과 브라우저를 조작하는 도구를 실행할 수 있습니다. [7장](#7-claude-code와-codex에서-쓰는-mcp) 참조), `proactiveEnabled`, `typingPauseSeconds`, `minSecondsBetweenProactiveAlerts`, `browser`입니다.

### 데이터 삭제하기

먼저 앱을 종료하세요(메뉴 ▸ **Copilot 종료**). 삭제는 되돌릴 수 없습니다.

```bash
# 기록과 설정 파일(폴더째 삭제. context.sqlite3*만 지워도 됩니다)
rm -rf ~/Library/Application\ Support/MyComputerAgent

# 환경설정
defaults delete com.buddypia.mca

# API 키
mca auth delete gemini        # anthropic, openai-compatible, typesafe도 같은 방식으로

# 권한 허용 상태
mca reset-permissions
```

키는 설정 ▸ 모델과 키의 **삭제**로도 지울 수 있습니다. 래핑용 항목은 키체인 접근에서 `com.buddypia.mca`를 검색해 삭제하세요. 마지막으로 `MyComputerAgent.app`을 삭제합니다. 채팅 스레드는 언제든 **채팅 지우기…**로 지울 수 있습니다.

## 15. 문제 해결

먼저 `mca doctor`를 실행하세요. 권한, 서명, Apple Intelligence, 키, 저장소, 라우팅을 보고합니다. 터미널에서 실행하면 터미널의 권한이 표시되므로, 실행 중인 앱의 설정 ▸ 접근 권한도 함께 확인하세요.

**윈도우도 Dock 아이콘도 보이지 않습니다.** 정상입니다. 메뉴바에서 별 모양 아이콘을 찾으세요(노치 뒤나 붐비는 메뉴바에 가려질 수 있습니다). 앱을 한 번 더 열면 설정이 열립니다.

**권한은 켜져 있는데 계속 빨간색이거나 "이 앱이 아니라 터미널에 부여되어 있습니다"라고 나옵니다.** 앱을 터미널에서 실행해서 macOS가 허용을 터미널에 부여한 것입니다. 종료한 뒤 `open build/MyComputerAgent.app`으로 다시 실행하세요. 권한을 바꾼 뒤에는 앱을 다시 실행하세요.

**다시 빌드했더니 권한을 다시 요청하거나, 스위치는 켜져 있는데 권한이 적용되지 않습니다.** ad-hoc 서명은 빌드할 때마다 바뀝니다. `mca reset-permissions`를 실행하고 앱을 다시 실행하여 다시 허용하거나, 정식 인증서로 서명하세요([설치와 빌드](#2-설치와-빌드) 참조).

**화면 기록, 마이크, 오디오 기록 목록에 "My Computer Agent"가 없습니다.** 앱이 한 번 권한을 요청한 뒤에 나타납니다. 앱이 실행 중인지 확인하고 설정 ▸ 접근 권한에서 **macOS에 전부 요청하기**를 누르세요.

**시스템 오디오 캡처가 대화상자도 없이 실패합니다(서명되지 않은 바이너리).** 서명되지 않은 바이너리에서는 `AudioHardwareCreateProcessTap`이 실패하며 macOS는 대화상자를 띄우지 않습니다. `mca doctor`는 "unsigned"라고 보고하고, `mca listen`은 바이너리가 서명되지 않았다고 출력합니다. `./Scripts/bundle.sh`로 빌드하고 그 번들을 실행하며, 정식 서명 ID를 사용하세요.

**Apple Intelligence가 켜져 있지 않습니다.** `mca doctor`의 "on-device gate"에 이 Mac이 Apple Intelligence를 지원하지 않음, 시스템 설정에서 Apple Intelligence가 꺼져 있음, 온디바이스 모델을 아직 다운로드 중임 중 하나가 표시됩니다. 시스템 설정 ▸ Apple Intelligence 및 Siri에서 켜세요. 해결할 수 있는 경우 설정 ▸ 모델과 키 ▸ **온디바이스**에 **Apple Intelligence 설정 열기** 버튼이 나타납니다. 켜지 않으면 분류 판정이 클라우드 모델로 대체되어 운영 비용이 늘어납니다. 지원하지 않는 Mac에서는 온디바이스 판정을 아예 쓸 수 없습니다.

**"API 키가 없습니다. 에이전트는 아무것도 답할 수 없습니다"라고 나옵니다.** 설정 ▸ 모델과 키에서 키를 추가하세요. 환경 변수가 앱에 전달되는 것은 그 환경에서 앱을 실행한 경우뿐입니다. `mca auth set`으로 추가한 키는 macOS가 "접근을 허용하겠습니까?" 대화상자를 기다리고 있을 수 있습니다. 설정 화면에서 다시 추가하세요. Mac을 초기화했거나 Secure Enclave를 리셋했다면 저장된 키를 읽을 수 없으므로 다시 입력해야 합니다.

**음성 입력이 시작되지 않습니다.** 설정 ▸ 일반 ▸ 언어를 확인하세요. 그 언어의 음성 모델이 다운로드 중(기다리기)이거나 이 Mac에서 지원되지 않을 수 있습니다(실시간 대화를 쓰거나 **말하는 언어**를 변경). 마이크 권한도 확인하세요. Gemini Flash 엔진을 골랐더라도 Gemini 키가 없으면 온디바이스 엔진을 사용합니다.

**단축키가 반응하지 않습니다.** 다른 앱이 그 단축키를 쓰고 있을 가능성이 높습니다. 설정 ▸ 단축키를 열면 사용 중인 단축키에 표시가 있습니다. 다른 단축키를 기록하세요.

**지켜보기가 저절로 멈췄습니다.** 연속 3회 실패했거나(API 키 없음이 흔한 원인입니다), 고정한 윈도우를 닫았거나, 고정한 모니터를 분리하면 멈춥니다. 이유는 채팅 스레드 아래 줄에 표시됩니다.

**특정 앱이나 페이지를 읽지 않습니다.** 제외 목록에 해당할 수 있습니다. 제목에 `sign in`이나 `password`가 들어간 윈도우, 비공개 브라우징 윈도우, 암호 관리 앱은 설계상 건너뜁니다. 이것이 원인이면 `mca capture`가 "EXCLUDED by the privacy filter"라고 출력합니다.

**패널이 클릭에 반응하지 않습니다.** 클릭 통과가 켜져 있습니다. `⌥⌘X`를 누르세요(아이콘이 사선이 그어진 커서 모양입니다).

**`mca act`가 "Accessibility permission is not granted"라고 합니다.** 실행 중인 터미널에 시스템 설정 ▸ 개인정보 보호 및 보안 ▸ 손쉬운 사용 권한을 주거나, `--dry-run`을 사용하세요.

## 16. 자주 묻는 질문

**API 키 없이도 쓸 수 있나요?** 기록, 로컬 검색, 로컬 GUI 판정은 쓸 수 있습니다. 질문에 대한 답변, 이미지 이해, 조언, 실시간 대화에는 최소한 Gemini 키(답변에는 다른 프로바이더의 키도 가능)가 필요합니다.

**화면이 업로드되나요?** 윈도우 텍스트와 OCR 결과는 로컬 데이터베이스에 남습니다. 텍스트나 이미지가 클라우드 모델로 전송되는 것은 질문했을 때, 화면 설명·영역 선택·화면 지켜보기를 사용했을 때, 또는 온디바이스 판정을 통과했을 때입니다. [개인정보 보호 방식](#13-개인정보-보호-방식)의 표를 참조하세요.

**완전히 오프라인으로 쓸 수 있나요?** 기록, 검색, 온디바이스 판정(Apple Intelligence 필요), 온디바이스 음성 인식(macOS 엔진 선택), 로컬 GUI 판정은 오프라인에서 동작합니다. 답변에는 클라우드 모델이 필요합니다.

**일시 중지하려면 어떻게 하나요?** 화면 지켜보기를 끄고, 음성 세션을 종료하거나, **Copilot 종료**로 종료하세요. `⌥⌘H`는 패널만 숨길 뿐 에이전트는 계속 지켜봅니다.

**음성 입력과 실시간 대화는 무엇이 다른가요?** 음성 입력은 말한 내용을 문자로 바꿔 일반 채팅 모델에 질문합니다. 실시간 대화는 음성을 Gemini로 스트리밍하고 음성으로 답합니다. [11장](#11-음성과-언어-설정)을 참조하세요.

**에이전트가 대신 클릭하고 입력해 주나요?** 네. `mca act`, 채팅 에이전트의 도구, MCP 도구를 통해 클릭, 문자 입력, 키 조작, AppleScript 실행, 파일 쓰기를 할 수 있습니다. `--dry-run`으로 미리 볼 수 있고, 자율 실행은 Ctrl+C로 멈출 수 있습니다.

**지원하는 언어는 무엇인가요?** 화면 표시, 음성 인식, 에이전트의 답변은 English, 日本語, 한국어를 지원합니다. 기본 제공 화면 지켜보기 목적은 일본어로 작성되어 있습니다.

**Intel Mac이나 오래된 macOS에서 동작하나요?** 아니요. macOS 26 이상과 Apple Silicon이 필요합니다.

**보안 문제는 어디에 신고하나요?** [SECURITY.md](../../SECURITY.md)에 안내된 방법으로 비공개로 신고해 주세요. 공개 issue로 올리지 마세요.
