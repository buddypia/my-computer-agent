## 1. 概要

MyComputerAgent（コマンド名は `mca`）は、macOS 向けのローカルファーストなデスクトップコパイロットです。作業中のウインドウの内容を読み取り、検索可能な履歴をお使いの Mac の中に保存し、画面に映っているものについての質問に答え、間違いやもっと速い方法に気づいたときには自分から声をかけます。マイクやシステム音声を聞き取ることもできますが、それはユーザーが求めたときだけです。

メニューバー（キラキラのアイコン）に常駐し、Dock にはアイコンを出しません。

**動作要件**

- macOS 26 以降、Apple Silicon 搭載の Mac
- ソースからビルドする場合は Xcode 26.6 以降（Swift 6.2 以降）
- API キーは任意です。キーがなくても、記録、ローカル検索、ローカルでの GUI 判定は動作します。クラウドモデルによる回答、画像理解、リアルタイム会話にはキーが必要です（[API キー](#5-api-キー)を参照）。

このマニュアルは、現時点のアプリの動作を説明しています。設計の背景は [README](../../README.ja.md)、セキュリティポリシーは [SECURITY.md](../../SECURITY.md) を参照してください。

## 2. インストールとビルド

ビルド済みのインストーラーはありません。ソースからアプリバンドルをビルドします。

```bash
git clone https://github.com/buddypia/my-computer-agent.git
cd my-computer-agent
./Scripts/bundle.sh
open build/MyComputerAgent.app
```

`Scripts/bundle.sh` は release ビルドを行い、`Info.plist` とエンタイトルメントを付けて `build/MyComputerAgent.app` にまとめ、署名します。

**バンドルの作成は省略できません。** macOS は署名済みのバンドル識別子（`com.buddypia.mca`）に対して権限を付与し、許可ダイアログの文面を `Info.plist` から読み込みます。`swift build` で作った単体のバイナリには、そのどちらもありません。特に未署名のバイナリでは、`AudioHardwareCreateProcessTap` がダイアログを一切出さずに失敗するため、アプリの不具合のように見えます。

### 署名

`bundle.sh` は次の順で署名 ID を選びます。第1引数で渡した ID、環境変数 `MCA_SIGN_IDENTITY`、「Developer ID Application」証明書、「Apple Development」証明書、最後にアドホック署名（`-`）です。

```bash
./Scripts/bundle.sh "Developer ID Application: Your Name (TEAMID)"
```

アドホック署名はバイナリのハッシュに固定されます。再ビルドのたびに macOS からは別のアプリに見えるため、権限をもう一度求められ、古い項目が一致しなくなることもあります。本物の証明書（Xcode ▸ Settings ▸ Accounts で作れる無料の Apple Development 証明書で十分です）で署名すれば、ID が安定してこの問題を避けられます。アドホック署名で再ビルドしたあとは、`mca reset-permissions` を実行してアプリを起動し直してください。

### 任意: アプリケーションフォルダに置く

`build/MyComputerAgent.app` を `/Applications` にコピーしても構いません。コマンドラインツールは、バンドルの中にあるバイナリです（[コマンドライン](#6-コマンドライン-mca)を参照）。

### 開発中の再ビルド

```bash
./Scripts/run.sh
```

バンドルを再ビルドし、古いプロセスを止めて、起動し直します。`swift build` のあとに `open` を実行するだけでは変更が反映されません。`swift build` はバンドルを更新せず、すでに動いているメニューバーアプリに対する `open` は設定ウィンドウを開き直すだけだからです。

## 3. アクセス権限

| 権限 | アプリが必要とする理由 | ないとどうなるか |
|---|---|---|
| **アクセシビリティ** | 他のアプリのウインドウのテキストと構造を読み取り、操作のためのクリックやキー入力を送ります。 | エージェントは何も見えません。 |
| **画面収録** | OCR による代替、画面の説明、範囲指定、画面の見守り、画面セレクターのサムネイルに使うスクリーンショット。 | アクセシビリティ情報を公開しないアプリで OCR による代替が効かず、セレクターにウインドウが表示されません。 |
| **マイク** | 音声入力とリアルタイム会話。 | あなたの声を拾えません。通話相手側しか文字起こしされません。 |
| **オーディオ収録** | CoreAudio のプロセスタップでシステム音声を取り込みます（仮想オーディオドライバは不要）。 | 会議の参加者の音声を拾えません。 |

システム設定 ▸ プライバシーとセキュリティでは、画面収録とオーディオ収録は同じ「**画面とシステムオーディオの収録**」にまとまっています。マイクの許可が必要になるのは、音声セッションを始めるときだけです。

### 許可はターミナルではなく、起動したアプリから行う

macOS は、権限を「責任を持つプロセス」に紐付けます。ターミナルから起動したバイナリの場合、それはターミナルです。したがって `mca doctor` から出たダイアログに答えると、権限は Terminal に付与され、エージェント本体には何も残りません。

1. `open build/MyComputerAgent.app` でアプリを起動します（ダブルクリックでも構いません）。
2. メニューバーのキラキラのアイコンを右クリックし、**アクセス権限…** を選びます（設定の「アクセス権限」タブが開きます）。
3. **macOS にすべて要求する** を押します。macOS がダイアログを出すのは、アプリの識別子につき1回だけです。以降は、アクセス権限タブのボタンからシステム設定の該当ペインへ移動してください。スイッチを切り替えるたびに、タブの表示が更新されます（**いま再確認する** で強制的に更新できます）。
4. macOS から再起動が必要だと言われたら、メニューの **Copilot を終了** でアプリを終了し、もう一度開きます。

「My Computer Agent」が画面収録、マイク、オーディオ収録の一覧に現れるのは、アプリが一度要求を出したあとです。見当たらない場合は、アプリが起動していることを確認し、アクセス権限タブからもう一度要求してください。

アクセス権限タブでは、各項目が **許可済み**、**未許可**、「このアプリではなくターミナルに付与されています」のいずれかで表示されます。ターミナルから起動している場合や、アドホック署名・未署名の場合は、警告も出ます。

`mca reset-permissions` は、`tccutil` を使って、このアプリのマイク、画面収録、アクセシビリティ、音声認識の許可を消去し、macOS が再びダイアログを出すようにします。

## 4. 初回起動

1. `MyComputerAgent.app` を開きます。Dock にアイコンもウインドウも出ませんが、メニューバーにキラキラのアイコンが現れます。起動時にアプリは権限を確認し、足りないものがあればダイアログを出します。
2. キラキラのアイコンを右クリックし、**設定…** を選びます（アプリをもう一度開いても設定が開きます）。
3. **アクセス権限** タブ: 上の手順で4つの権限を許可します。
4. **モデルとキー** タブ: Gemini のキーを貼り付けて **保存** を押します（任意ですが推奨です。[API キー](#5-api-キー)を参照）。再起動なしですぐに有効になります。
5. `⌥Space` を押してチャットを開き、画面に映っているものについて質問してみてください。
6. ターミナルからの確認（任意）: `build/MyComputerAgent.app/Contents/MacOS/mca doctor`

起動した時点では、聞き取りや画面の画像送信につながるものは、何も動いていません。マイクは閉じており、**画面を見守る** はオフです。詳しくは[プライバシーの仕組み](#13-プライバシーの仕組み)を参照してください。

## 5. API キー

キーは任意です。どの機能にどのキーが必要かは、次のとおりです。

| プロバイダ | 設定上の名前（id） | 環境変数 | 役割 |
|---|---|---|---|
| Google Gemini | `gemini` | `GEMINI_API_KEY`（または `GOOGLE_API_KEY`） | 分類・回答・画像理解・高度な推論の主経路、リアルタイム会話、Gemini Flash による文字起こし。 |
| Anthropic | `anthropic` | `ANTHROPIC_API_KEY` | 回答と画像理解のフォールバック。 |
| OpenAI 互換 | `openai-compatible` | `OPENAI_API_KEY` | 回答と画像理解のフォールバック（接続先は `https://api.openai.com/v1`）。 |
| TypeSafe AI (Jev) | `typesafe` | `TYPESAFE_API_KEY` | 操作のための低遅延な GUI 判定。キーがなければ、ローカルの決定論的な意味一致で代替します。 |

既定のルーティングでは、「割り込む価値があるか」の一次判定に Apple のオンデバイスモデルを使い、分類・回答・画像理解・高度な推論には `gemini-3.8-flash` を使います。回答と画像理解のフォールバックは Anthropic と OpenAI 互換のモデルです。`mca doctor` はルーティングの一覧を表示し、実行できない経路に印を付けます。

### キーの追加（推奨の方法）

設定 ▸ **モデルとキー** ▸ **API キー** で、キーを貼り付けて **保存** を押します。キーチェーンの項目をアプリ自身が書き込むため、あとで読み戻すときに「アクセスを許可しますか？」というダイアログが出ません。保存済みのキーが再表示されることはなく、**置き換え**または**削除**ができます。各プロバイダには、キーの出どころが「キーチェーンに保存済み」「$変数名 から取得」「キーなし」のいずれかで表示されます。

### キーの保存方法（`SecretStore`）

キーは平文では保存されません。各キーは、この Mac の Secure Enclave の中で生成した P-256 鍵に対して HPKE（RFC 9180、`P256_SHA256_AES_GCM_256`）で封印され、暗号文だけがログインキーチェーンに入ります。プロバイダ名が認証付き追加データとして結び付けられているため、ある項目を別のプロバイダの枠に移すことはできません。

- 古いビルドで保存されたキーは、最初に読み出されたときに自動で封印し直されます。
- Mac を初期化したり Secure Enclave をリセットしたりすると、保存済みのキーは読めなくなります（意図的に端末へ結び付けているためです）。キーを貼り付け直してください。アプリは「キーなし」ではなく、その旨を表示します。
- Secure Enclave のない Mac ではソフトウェアの鍵でラップし、設定画面にオレンジ色でその旨が表示されます。

### 環境変数

環境変数に空でない値が設定されていれば、キーチェーンより優先され、どこにも書き込まれません。開発時や、シェルから起動する `mca` コマンドで便利です。

- Finder や `open` で起動したメニューバーアプリは、シェルのプロファイルの環境変数を**引き継ぎません**。アプリには設定画面を、ターミナルから起動するコマンド（MCP クライアントが起動する `mca mcp` を含む）には環境変数を使ってください。
- アプリは `.env` ファイルを読み込みません。リポジトリの `.env.example` は変数名の一覧にすぎません。シェルや MCP クライアントの設定の中で設定してください。

### コマンドライン

```bash
mca auth set gemini        # 標準入力から読み取るので、シェルの履歴にキーが残りません
mca auth delete gemini
```

プロバイダは `gemini`、`anthropic`、`openai-compatible`、`typesafe` です。CLI で保存したキーは CLI のバイナリのものになるため、アプリが初めて読み出すときに macOS が許可を求めます。気づきにくく、「キーがない」状態と区別がつきません。設定画面からの追加をおすすめします。

## 6. コマンドライン mca

実行ファイルはアプリバンドルの中にあります。エイリアスを作っておくと便利です。

```bash
alias mca="/path/to/MyComputerAgent.app/Contents/MacOS/mca"
```

コマンドを付けずに実行するとアプリが起動します（`mca run`）。コマンドの前に置くグローバルオプションとして、`--debug` または `-d` で詳細ログを有効にできます（`MCA_DEBUG=1` と同じです）。

| コマンド | 内容 |
|---|---|
| `mca run` | コパイロットとメニューバーアイコンを起動します（既定）。 |
| `mca doctor` | 読み取り専用のレポート。権限、コード署名、Apple Intelligence の可否、どのプロバイダのキーがあるか、履歴データベースのパスと保存件数、ルーティングを表示します。 |
| `mca listen [秒数]` | 指定秒数（既定 20）だけ取り込んで文字起こしし、マイクとシステム音声の2チャンネルを別々に表示します。 |
| `mca capture [秒数]` | 指定秒数（既定 0）待ってから、アクティブなウインドウを1回読み取り、抽出した内容を表示します。プライバシーフィルターの除外対象だった場合はその旨を表示します。 |
| `mca ask "質問"` | 現在のデスクトップの文脈を使ったワンショットの質問。回答は標準出力にストリーミングされます。 |
| `mca search "検索語"` | 記録された履歴を検索します（オンデバイスのクエリ拡張つき）。最大 20 件を表示します。 |
| `mca act …` | 画面操作を実行します（下記）。 |
| `mca browser …` | 要素の参照を使って Chromium 系ブラウザを操作します（下記）。 |
| `mca mcp` | 標準入出力で MCP サーバーとして動作します（[第7章](#7-claude-code-と-codex-から使う-mcp)）。 |
| `mca auth set\|delete <provider>` | プロバイダの API キーを保存または削除します。 |
| `mca setup` | 権限設定のウォークスルーを開きます（起動中のアプリの設定 ▸ アクセス権限を推奨）。 |
| `mca reset-permissions` | このアプリの TCC 権限を消去し、macOS が再びダイアログを出すようにします。 |
| `mca help` | 使い方を表示します。 |

ターミナルから実行するコマンド（`doctor`、`listen`、`capture`、`ask`、`act`）が示すのは、アプリではなく**ターミナル**の権限です。`mca doctor` は、これを検知すると警告を表示します。

### `mca act`

```text
mca act [options] [<goal>]
  --goal, -g <text>        自然言語の目標（--autonomous を含意します）
  --autonomous, -a         サブゴールを立てて、完了するまで繰り返します
  --max-steps, -s <n>      ステップ数の上限（既定 20）
  --confidence, -c <0-1>   最低限の確信度（既定 0.80）
  --dry-run, -n            クリックやキー入力は送らず、計画と判断だけを行います
```

```bash
mca act "検索ボタンをクリック"                                       # 1ステップ
mca act --goal "Safari を開いて東京の天気を検索" --dry-run          # プレビューのみ
mca act --autonomous --max-steps 15 "登録フォームに入力"
```

このコマンドは実際にマウスを動かし、文字を入力します。まず `--dry-run` で試してください。自律実行は Ctrl+C で中断できます。`--dry-run` なしで実行するには、ターミナルにアクセシビリティの権限が必要です。

### `mca browser`

DevTools のエンドポイント（`127.0.0.1` のポート 9222 と 9333 を順に試します）を通じてブラウザを操作し、見つからなければ最前面のブラウザウインドウに対して macOS のアクセシビリティで代替します。専用のタブを開き、ユーザーのタブは操作しません。

```text
navigate <url> | snapshot [--filter T] [--max-depth N] | click <ref> | fill <ref> <text>
type [<ref>] <text> | press <key> | select <ref> <option> | scroll <ref> <percent>
act "<instruction>" | observe ["<instruction>"] | extract "<instruction>"   （モデルが必要です）
text | url | title | tabs | tab new|switch|close | wait … | eval "<js>" | screenshot [path]
back | forward | reload
```

すべての一覧は `mca browser help` で確認できます。

## 7. Claude Code と Codex から使う MCP

`mca mcp` は、**標準入出力**で Model Context Protocol のサーバーとして動作します。ネットワークポートは開きません。クライアントがサブプロセスとして起動します。

**公開されるツール**

| ツール | 用途 |
|---|---|
| `search_context` | ユーザーが見聞きしたことを検索します（検索語、直近 N 分、アプリ、件数）。 |
| `recent_activity` | ユーザーが最近していたこと。 |
| `conversation_history` | 直近の会話の文字起こし（`me`、`others`、`all`）。 |
| `computer` | 座標を指定したマウスとキーボードの操作。 |
| `click_element` | タイトルやラベルで UI 要素をクリックします。 |
| `run_applescript` | AppleScript を実行します。 |
| `inspect_ui_elements` | アクティブなウインドウの操作可能な要素を一覧します。 |
| `typesafe_act` | 自然言語の目標から GUI 操作を1回行います。 |
| `autonomous_act` | ステップ上限、確信度のしきい値、ドライランを指定できる複数ステップの目標実行。 |
| `browser_*` | ブラウザ操作ツール（navigate、snapshot、element、act、observe、extract、read、tabs、wait、evaluate）。`config.json` でブラウザ自動操作を無効にしていなければ含まれます。 |

**Claude Code**

```bash
claude mcp add my-computer-agent -- /path/to/MyComputerAgent.app/Contents/MacOS/mca mcp
```

**Codex CLI**（`~/.codex/config.toml`）

```toml
[mcp_servers.my-computer-agent]
command = "/path/to/MyComputerAgent.app/Contents/MacOS/mca"
args = ["mcp"]
```

補足:

- サーバーはアプリと同じ履歴データベースを読みます。検索できる内容が入るように、先にアプリを起動しておいてください（過去に起動していれば構いません）。
- 権限は、サーバーを起動したプログラム（ターミナルやエディタ）に紐付きます。コンピューター操作系のツールには、そのプログラムのアクセシビリティ権限が必要です。履歴の検索には特別な権限は要りません。
- **危険なツールは、MCP 経由では既定で拒否されます。** MCP クライアントにはあなたへ確認を表示する手段がないため、`run_applescript`、`computer`、`click_element`、`typesafe_act`、`autonomous_act`（ドライランでない場合）、ページを操作するブラウザツール（`browser_navigate`、`browser_element`、`browser_act`、タブを開く・切り替える・閉じる場合の `browser_tabs`、`path` を指定した `browser_read`）、そして `browser_evaluate` はエラーを返します。読み取り系のツール（検索、履歴、`inspect_ui_elements`、`browser_snapshot`、`browser_observe`、`browser_extract`、`browser_wait`、読み取り用途の `browser_read` と `browser_tabs`）は通常どおり使えます。信頼できるクライアントに対してのみ許可したい場合は、`config.json` に `"mcpAllowDangerousTools": true` を設定し、クライアントを再起動してください。詳しくは [SECURITY.ja.md](../../SECURITY.ja.md) の第5項を参照してください。
- `computer`、`click_element`、`run_applescript`、act 系のツールは、接続したエージェントにあなたの Mac を操作させます。信頼できるクライアントだけを接続し、試すときは `dry_run` を使ってください。
- プロバイダのキーはアプリと同じ順で解決されます。まず環境変数（たとえば `GEMINI_API_KEY`。クライアントの環境から引き継がれます）、次にキーチェーンです。

## 8. メニューバーアイコンとパネル

キラキラのアイコンがアプリの本体です。

- **左クリック**: コパイロットのパネルがポップオーバーとして開きます。カード、質問欄、不具合のある箇所が表示されます。ほかの場所をクリックすると閉じます。カードにカーソルを重ねると ✕ が出て、カードを消せます（同じ内容はチャットに残ります）。
- **右クリック**（または Control を押しながらクリック）: メニューが開きます。
- パネルを閉じているあいだにカードが届くと、アイコンに件数が出ます。クリック透過がオンのあいだは、アイコンがスラッシュ付きのカーソルに変わります。ツールチップに現在の状態が出ます。不具合のあるサブシステムは、メニューの先頭に警告マーク付きで表示されます。

**メニューの項目**

| 項目 | 内容 |
|---|---|
| デスクトップにパネルを表示 | オフ（既定）ではパネルはポップオーバーです。オンにすると、画面の隅に浮かぶウインドウになります。 |
| 細いバーにたたむ / 元の大きさに戻す | 浮かぶパネルを、細いタイトルバーだけにします。 |
| 常に最前面に表示 | オンにすると、すべての Space とフルスクリーンアプリの上でも前面に残ります。オフでは通常のウインドウとして動作します。 |
| クリックを背面に通す | オンにすると、パネル自身のボタンへのクリックも含め、パネルへのすべてのクリックが背面のアプリに届きます。`⌥⌘X` かこのメニューでオフにできます。 |
| 表示位置 | 上または下、左または右。クリック透過がオフなら、パネルをドラッグして動かすこともでき、動かした位置が記憶されます。 |
| チャットを開く… | チャットウィンドウを開きます（`⌥Space`）。 |
| 範囲を選択して説明… | 画面の一部をドラッグして選び、説明させます。Esc でキャンセルします。 |
| チャットを消去… | 確認のあと、すべてのメッセージを消去します。 |
| 見守る画面を選ぶ… | 画面セレクターを開きます。見守っている対象があれば、項目名にその対象が出ます。 |
| リアルタイム会話を始める / 音声入力を始める | 2つの音声モード（[第11章](#11-音声と言語の設定)）。 |
| 設定… | メニューを開いているあいだは `⌘,`。 |
| アクセス権限… | 設定 ▸ アクセス権限を開きます。 |
| Copilot を終了 | メニューを開いているあいだは `⌘Q`。 |

ウインドウに関する項目（たたむ、最前面、クリック透過、表示位置）は浮かぶパネルに対するもので、パネルがオフのあいだは薄く表示されます。これらの選択はすべて、次回の起動後も保たれます。設定 ▸ **パネル** には同じスイッチがあり、さらに **スクリーンショットにパネルを写す**（既定はオフ。[プライバシーの仕組み](#13-プライバシーの仕組み)を参照）があります。

## 9. チャットウィンドウ

`⌥Space`、パネルの **チャット** ボタン、またはメニューの **チャットを開く…** で開きます。画面の中央の前面に開き、入力欄にはすでにカーソルがあります。意図的にモーダルにはしていないため、ほかの作業はそのまま続けられます。Esc で閉じます。

回答とエージェント自身の気づきは、1つのスレッドにまとまります。送信は Return です。メッセージを右クリックすると、**コピー**、**このメッセージを消す**、**ここまでをまとめて消す** が選べます。ごみ箱のアイコン（またはメニューの **チャットを消去…**）は、確認のあと新しい会話を始めます。スレッドはセッションのあいだ、メモリ上に保持されます。

**ツールバー**

| 操作 | 内容 |
|---|---|
| **画面を説明** (Explain) | ワンショット。セレクターが指している対象を見て、チャットで説明します。何も固定していなければ、ポインタのあるディスプレイが対象です。画像を使うので、描画ベースのアプリ（図、PDF、ビデオ会議）でも使えます。 |
| **範囲指定** (Snip) | 画面の一部をドラッグして選び、説明させます。 |
| **画面を見守る** (Continuous Watch) | 画面の見守りをオン・オフします（次章）。動作中は「見守り中」または「確認中…」と表示されます。 |
| ピンのボタン | 画面セレクターを開きます。固定中のウインドウやディスプレイ、または見守り中の画面数が表示されます。 |
| 間隔のメニュー | 画面を見る間隔: 15秒ごと、45秒ごと、2分ごと。 |
| マイク | **音声入力**（Dictation）。 |
| 波形 | **リアルタイム会話**（Live conversation）。 |
| ごみ箱 | 新しい会話を始めます。 |

入力欄の横には **プリセット** のバー（「プリセット選択で遂行」）があり、現在の対象が表示されます。プリセットは、現在の対象に対して1回だけ実行されます（「今すぐ1回実行」）。そのメニューからは、継続的な見守りの目的に設定したり、編集や削除をしたりもできます。

## 10. 画面の見守りと画面セレクター

### 画面を見守る（Continuous Watch）

既定ではオフで、起動のたびにオフに戻ります。オンにすると、エージェントは一定間隔で対象を見て、間違い、エラー、リスク、もっと速い方法に気づいたときだけ発言します。スレッドの下の行に最後の動作が表示されるので、静かな見守りと故障を見分けられます。

前回から変化のない画面、除外リストのアプリ、このアプリ自身のウインドウ、そして依頼した回答をストリーミング中のあいだは、何も送信しません。3回続けて失敗すると、見守りを止めて理由（たとえば API キーがない）を表示します。

固定した対象は、小さなグレースケールに縮小した粗い画像で比較します。このため、点滅するカーソルは変化とみなされず、ビルドの終了は変化とみなされます。固定したウインドウが閉じられたり、固定したモニターが外されたりすると、別の場所へ移らずに見守りを止めます。何かを固定しているあいだは、フォーカスに連動した取り込みを止めるため、固定した対象が履歴の中で最新の状態に保たれます。

### 画面セレクター

チャットのピンのボタン、パネルの **画面** ボタン、メニューの **見守る画面を選ぶ…** で開きます。ライブのサムネイル（開いているあいだは3秒ごとに更新）が、**ウインドウ** と **画面全体** の2つのグループで並びます。

- タイルをクリックして選択します。ダブルクリックするか、**この画面を見る**（Return）を押すと適用されます。適用すると、見守りがオフだった場合はオンになります。Esc または **キャンセル** で閉じます。
- **前面のウインドウ** は、手前にあるウインドウを追いかけます。固定した**ウインドウ**は、どこへドラッグしても中身を追い続けます。固定した**ディスプレイ**は、机の上の一区画を押さえ、そこに現れるものを見守ります。
- タイルの角の丸いボタンで、複数の対象をまとめて選べます。そのときボタンは「N 画面を見守り開始」になります。対象ごとに **目的** のメニューがあり、組み込みの目的（汎用アドバイス、エラー診断、要約・議事録、タスク・ToDo 抽出、コードレビュー、ミーティング支援、AI CLI 開発監視、仕様・デザイン照合）のほか、**カスタム目的を編集…** で独自のものを作れます。組み込みの目的は日本語で書かれています。
- 除外対象のアプリにはタイルが出ません。除外対象のウインドウは、ディスプレイのタイルや送信内容からも外されます。セレクター自身のウインドウは画面キャプチャから隠されます。
- 一覧が空のときは、たいてい画面収録が許可されていません。

`⌥⌘W` は、セレクターを開かずに、いま作業中のウインドウを固定します（見守りも開始します）。もう一度押すと解除されます。

### 範囲指定（Snip）

**範囲指定**（チャットのツールバー、パネル、メニュー）を選ぶと、画面が暗くなり、四角形をドラッグして選べます。選んだ範囲がモデルに送られ、説明が返ります。Esc でキャンセルできます。

## 11. 音声と言語の設定

### 2つの音声ボタン

- **音声入力**（Dictation、マイク）: 話した内容を文字にして、打ち込んだ質問と同じチャットモデルに渡します。画面の文脈やツールもそのまま使えます。音声が Mac の外に出るかどうかは、音声認識エンジン（後述）で決まります。
- **リアルタイム会話**（Live conversation、波形）: Gemini が1つの接続で声を聞き、声で答えます。最新の情報が必要なときは Web も検索します。**会話が開いているあいだ、マイクの音声は Google に送られ続けます。** Gemini のキーが必要です。

ボタンを押すと開始、もう一度押すと終了、セッション中にもう一方を押すと切り替わります。`⌃⌥V` は、最後に使ったモードを開始し、もう一度押すと終了します。マイクが聞き取った内容は、作業中の画面の下部に大きな文字で表示され、チャットの音声バーにも出て、ターンが終わると通常のユーザーメッセージとして会話に追加されます。確定した文字とエンジンの暫定の推測は、濃さを変えて描かれます。大きな字幕は、設定 ▸ 一般 ▸ **音声での会話** でオフにできます。

起動時、マイクは開いていません。音声セッションを始めると開き、終わると閉じます。マイクとシステム音声のタップを開いたままにするには、設定 ▸ 一般 ▸ **音声の取り込み** の **常にマイクで聞き取る** をオンにします（既定はオフ。マイクのダイアログが出たり、音声モデルのダウンロードが始まったりすることがあります）。

### 言語（設定 ▸ 一般 ▸ 言語）

- **表示**: English、日本語、한국어、または **macOS に合わせる**（既定）。メニュー、設定、権限の画面の言語と、エージェントが回答や助言を書く言語が、これで決まります。すぐに反映されます。
- **認識エンジン**: **Gemini Flash (クラウド・高精度)** または **macOS (オンデバイス・完全ローカル)**。既定は Gemini Flash で、文字起こしのために音声を Gemini に送ります。Gemini のキーが保存されていなければ、オンデバイスのエンジンを使います。音声を Mac の外に出したくない場合は、**macOS (オンデバイス・完全ローカル)** を選んでください。
- **話す言語**: 自動（既定）、English、日本語、한국어。**自動は表示言語に従います**。話されている言語を検出するわけではありません。設定には、決まった言語（たとえば「自動 → 한국어 (ko-KR)」）と、その言語のオンデバイスモデルがインストール済みか、ダウンロード可能か、未対応かが表示されます。初回の音声入力がしばらく止まるのは、たいていモデルのダウンロード中です。お使いの Mac が言語に未対応の場合、音声入力は始まりませんが、リアルタイム会話は使えます。

話す言語が変わると文字起こしが再起動するため、切り替えの前後の数秒間の音声は取り込まれません。macOS やモデルのプロバイダが返すエラーの文章は、届いたままの元の言語で表示されます。`mca` コマンドラインは英語のみです。

## 12. キーボードショートカット

既定値（すべてグローバルで、すべて変更できます）:

| ショートカット | 動作 |
|---|---|
| `⌥Space` | 質問する: チャットを開き、入力欄にカーソルを置きます |
| `⌥⌘H` | パネルの表示 / 非表示（エージェントは見守りを続けます） |
| `⌥⌘J` | パネルをたたむ / 戻す |
| `⌥⌘X` | クリックを背面に通す（切り替え） |
| `⌃⌥V` | 音声での会話の開始 / 終了（最後に使ったモード） |
| `⌥⌘W` | このウインドウを見張る（固定。もう一度押すと解除） |

そのほかのキー: `Esc` はチャットウィンドウを閉じ、範囲指定と画面セレクターをキャンセルします。`Return` はメッセージを送信し、セレクターの選択を適用します。メニューバーのメニューを開いているあいだは `⌘,` と `⌘Q` が使えます。`⌘W` は従来どおりウインドウを閉じます。Option キーを含むキーの組み合わせ全体が登録されているためです。

設定 ▸ **ショートカット** では、新しいキーの記録、ショートカットの消去（メニューバーからは引き続き操作できます）、**デフォルトに戻す** ができます。macOS は、グローバルなショートカットを最初に登録したアプリに割り当て、ほかのアプリには何も知らせません。そのためこのタブでは、ほかのアプリに使われているキーに印を付け、別の操作にすでに割り当てたキーを拒否し、macOS がテキスト編集用に予約しているキー（`⌘V` など）も拒否します。

## 13. プライバシーの仕組み

**起動時はオフ。** マイクとシステム音声のタップは、音声セッションを始める（または「常にマイクで聞き取る」をオンにする）まで閉じています。画面の画像を送る **画面を見守る** はオフで、起動のたびにオフから始まります。

**既定で記録されるもの。** アクセシビリティが許可されていると、OS のイベント（フォーカスの変更、ウインドウタイトルの変更、入力の休止）をきっかけに、アクティブなウインドウのテキストを読み取ります。アクセシビリティ情報を公開しないアプリではオンデバイスの OCR で代替し、ローカルの SQLite データベースに保存します。音声を取り込んだ場合は、話された内容の文字起こしも保存されます。30 日より古い記録は自動で削除されます。フレームレートでの定期的な監視は行いません。

**読み取らないもの、フィルターされるもの**

- 除外対象のアプリとウインドウ。既定では、次のバンドル ID は何かを保存する前にスキップされます: 1Password、Bitwarden、キーチェーンアクセス、LastPass、Dashlane、Apple のパスワード。ウインドウタイトルに `private browsing`、`incognito`、`シークレット`、`password`、`パスワード`、`sign in`、`2fa`、`one-time code` を含むもの（大文字と小文字は区別しません）も、同様にスキップされます。どちらの一覧も `config.json` で変更できます（[第14章](#14-データの保存場所と削除方法)）。
- パスワード管理アプリ（1Password、Bitwarden、Apple のキーチェーンアクセスとパスワード、KeePassXC）に対する操作は、ハードブロックされています。エージェントはこれらのアプリの中を調べることも、クリックすることもしません。
- パスワード欄（`AXSecureTextField`）は、ウインドウの読み取りでスキップされ、操作ツールに見える UI 要素からも取り除かれます。
- 操作系の処理では、UI のラベルや値がモデルに届く前にパターンマッチで伏せ字にされます。対象は、API キー、Bearer トークン、シークレットのような文字列、`sk-…`、`ghp_…`、`AKIA…` 形式のトークン、16 桁のカード番号です。
- 固定したディスプレイでは、除外対象のウインドウはキャプチャの内部で取り除かれるため、ぼかされるのではなく画像に存在しません。
- このアプリ自身のウインドウは、エージェントが自分の回答を読み返さないよう、画面キャプチャから隠されています。浮かぶパネルは、**スクリーンショットにパネルを写す**（既定はオフ）でキャプチャに写せます。

**Mac の中に残るものと、外に出ることがあるもの**

| データ | 行き先 |
|---|---|
| 取り込んだウインドウのテキスト、OCR、履歴、検索インデックス | Mac 上のローカルデータベースの中に残ります。 |
| オンデバイスの「割り込む価値があるか」の判定 | Apple のオンデバイスモデル。通過したものだけがクラウドモデルに届きます。Apple Intelligence がないと、この判定はクラウドモデルで代替されます。 |
| あなたの質問、その文脈とツールの結果 | 回答するモデルのプロバイダに送られます（既定は Gemini、次に Anthropic や OpenAI 互換のフォールバック）。 |
| 画面の説明、範囲指定、画面の見守りで使う画像 | クラウドの画像理解モデルに送られます。 |
| 音声入力の音声 | オンデバイスのエンジン: Mac の中にとどまり、送られるのは文字だけです。Gemini Flash のエンジン: 文字起こしのために音声が Gemini に送られます。 |
| リアルタイム会話の音声 | 会話が開いているあいだ、Google にストリーミングされます。 |
| API キー | Secure Enclave に封印され、暗号文だけがログインキーチェーンに入ります。 |

クラウドとの通信はすべて TLS（HTTPS または WSS）です。MCP サーバーは標準入出力のみを使い、待ち受けポートは開きません。脆弱性の報告は [SECURITY.md](../../SECURITY.md) を参照してください。

## 14. データの保存場所と削除方法

| 内容 | 場所 |
|---|---|
| 履歴データベース（記録と検索インデックス） | `~/Library/Application Support/MyComputerAgent/context.sqlite3`（`-wal` と `-shm` ファイルを伴います） |
| 任意の設定ファイル | `~/Library/Application Support/MyComputerAgent/config.json` |
| `mca browser` の状態 | `~/Library/Application Support/MyComputerAgent/browser-cli.json`（アプリが専用の Chrome を起動した場合のみ `chrome-profile/` も） |
| パネル、ショートカット、言語、音声、見守りの環境設定 | 環境設定ドメイン `com.buddypia.mca` |
| API キー（暗号文）とラッピング用の項目 | ログインキーチェーン。サービス名は `com.buddypia.mca.providers` と `com.buddypia.mca.wrapping-key` |
| 権限の許可状態 | macOS のプライバシーデータベース（TCC）。システム設定 ▸ プライバシーとセキュリティで確認できます |

`config.json` は任意で、アプリが設定を保存したときに作られます。書かなかったキーは既定値のままで、変更は次回の起動で反映されます。主なキーは `retentionDays`（既定 30）、`excludedBundleIDs`（バンドル ID の前方一致。指定すると既定の一覧を**置き換える**ので、残したい既定値は書き写してください）、`excludedWindowPatterns`、`mcpAllowDangerousTools`（既定 `false`。`true` にすると MCP クライアントが確認なしでMacやブラウザを操作するツールを実行できます。[第7章](#7-claude-code-と-codex-から使う-mcp)参照）、`proactiveEnabled`、`typingPauseSeconds`、`minSecondsBetweenProactiveAlerts`、`browser` です。

### データを削除する

先にアプリを終了してください（メニュー ▸ **Copilot を終了**）。削除は元に戻せません。

```bash
# 履歴と設定ファイル（フォルダごと削除。context.sqlite3* だけでも構いません）
rm -rf ~/Library/Application\ Support/MyComputerAgent

# 環境設定
defaults delete com.buddypia.mca

# API キー
mca auth delete gemini        # anthropic、openai-compatible、typesafe も同様に

# 権限の許可状態
mca reset-permissions
```

キーは、設定 ▸ モデルとキーの **削除** からも消せます。ラッピング用の項目は、キーチェーンアクセスで `com.buddypia.mca` を検索して削除してください。最後に `MyComputerAgent.app` を削除します。チャットのスレッドは、いつでも **チャットを消去…** で消去できます。

## 15. トラブルシューティング

まず `mca doctor` を実行してください。権限、署名、Apple Intelligence、キー、ストレージ、ルーティングを報告します。ターミナルから実行した場合はターミナルの権限が表示されるため、起動中のアプリの設定 ▸ アクセス権限も合わせて確認してください。

**ウインドウも Dock のアイコンも出ない。** 正常です。メニューバーのキラキラのアイコンを探してください（ノッチの裏や、混み合ったメニューバーに隠れることがあります）。アプリをもう一度開くと設定が開きます。

**権限はオンなのに赤いまま、または「このアプリではなくターミナルに付与されています」と出る。** アプリをターミナルから起動したため、macOS が許可をターミナルに紐付けています。終了して、`open build/MyComputerAgent.app` で起動し直してください。権限を切り替えたあとは、アプリを起動し直してください。

**再ビルドしたら権限をもう一度求められる、またはスイッチはオンなのに権限が効かない。** アドホック署名は、ビルドのたびに変わります。`mca reset-permissions` を実行し、アプリを起動し直して許可し直すか、本物の証明書で署名してください（[インストールとビルド](#2-インストールとビルド)を参照）。

**画面収録、マイク、オーディオ収録の一覧に「My Computer Agent」がない。** アプリが一度要求を出したあとに現れます。アプリが起動していることを確認し、設定 ▸ アクセス権限の **macOS にすべて要求する** を押してください。

**システム音声の取り込みが、ダイアログも出さずに失敗する（未署名のバイナリ）。** 未署名のバイナリでは `AudioHardwareCreateProcessTap` が失敗し、macOS はダイアログを出しません。`mca doctor` は「unsigned」と報告し、`mca listen` はバイナリが未署名であることを表示します。`./Scripts/bundle.sh` でビルドし、そのバンドルを実行し、本物の署名 ID を使ってください。

**Apple Intelligence が有効になっていない。** `mca doctor` の「on-device gate」に、この Mac は Apple Intelligence に対応していない、Apple Intelligence がシステム設定でオフになっている、オンデバイスモデルをまだダウンロード中、のいずれかが表示されます。システム設定 ▸ Apple Intelligence と Siri でオンにしてください。対処できる場合は、設定 ▸ モデルとキー ▸ **オンデバイス** に **Apple Intelligence の設定を開く** ボタンが出ます。使えないと、トリアージはクラウドモデルで代替され、運用コストが上がります。対応していない Mac では、オンデバイスの判定は使えません。

**「API キーがありません。エージェントは何も回答できません」と出る。** 設定 ▸ モデルとキーでキーを追加してください。環境変数がアプリに届くのは、その環境からアプリを起動した場合だけです。`mca auth set` で追加したキーは、macOS が「アクセスを許可しますか？」のダイアログを待っている場合があります。設定画面から追加し直してください。Mac を初期化したり Secure Enclave をリセットしたりした場合、保存済みのキーは読めなくなるため、入力し直してください。

**音声入力が始まらない。** 設定 ▸ 一般 ▸ 言語を確認してください。その言語の音声モデルがダウンロード中（待つ）か、この Mac で未対応（リアルタイム会話を使うか、**話す言語** を変更）かもしれません。マイクの権限も確認してください。Gemini Flash のエンジンを選んでいても、Gemini のキーがなければオンデバイスのエンジンを使います。

**ショートカットが反応しない。** ほかのアプリがそのキーを使っている可能性があります。設定 ▸ ショートカットを開くと、使われているキーに印が付いています。別のキーを記録してください。

**見守りが勝手に止まった。** 3回続けて失敗した場合（API キーがないのが典型的な原因です）、固定したウインドウを閉じた場合、固定したモニターを外した場合に止まります。理由は、チャットのスレッドの下の行に表示されます。

**特定のアプリやページが読み取られない。** 除外リストに該当している可能性があります。タイトルに `sign in` や `password` を含むウインドウ、プライベートブラウジングのウインドウ、パスワード管理アプリは、仕様としてスキップされます。これが原因の場合、`mca capture` は「EXCLUDED by the privacy filter」と表示します。

**パネルがクリックに反応しない。** クリック透過がオンです。`⌥⌘X` を押してください（アイコンがスラッシュ付きのカーソルになっています）。

**`mca act` が「Accessibility permission is not granted」と言う。** 実行しているターミナルに、システム設定 ▸ プライバシーとセキュリティ ▸ アクセシビリティの許可を与えるか、`--dry-run` を使ってください。

## 16. よくある質問

**API キーなしでも使えますか。** 記録、ローカル検索、ローカルでの GUI 判定は使えます。質問への回答、画像理解、助言、リアルタイム会話には、少なくとも Gemini のキー（回答には別のプロバイダのキーでも可）が必要です。

**画面はアップロードされますか。** ウインドウのテキストと OCR の結果は、ローカルのデータベースに残ります。テキストや画像がクラウドモデルに送られるのは、質問したとき、画面の説明・範囲指定・画面の見守りを使ったとき、またはオンデバイスの判定を通過したときです。[プライバシーの仕組み](#13-プライバシーの仕組み)の表を参照してください。

**完全にオフラインで使えますか。** 記録、検索、オンデバイスの判定（Apple Intelligence が必要）、オンデバイスの文字起こし（macOS のエンジンを選択）、ローカルでの GUI 判定はオフラインで動きます。回答にはクラウドモデルが必要です。

**一時停止するには。** 画面の見守りをオフにし、音声セッションを終了するか、**Copilot を終了** で終了します。`⌥⌘H` はパネルを隠すだけで、エージェントは見守りを続けます。

**音声入力とリアルタイム会話の違いは。** 音声入力は、話した内容を文字にして通常のチャットモデルに質問します。リアルタイム会話は、声を Gemini にストリーミングして、声で答えます。[第11章](#11-音声と言語の設定)を参照してください。

**エージェントは、代わりにクリックや入力をしてくれますか。** はい。`mca act`、チャットのエージェントのツール、MCP のツールを通じて、クリック、文字入力、キー操作、AppleScript の実行、ファイルの書き込みができます。`--dry-run` でプレビューでき、自律実行は Ctrl+C で止められます。

**対応言語は。** 表示、音声認識、エージェントの回答は、English、日本語、한국어に対応しています。組み込みの画面見守りの目的は、日本語で書かれています。

**Intel Mac や古い macOS で動きますか。** いいえ。macOS 26 以降と Apple Silicon が必要です。

**セキュリティ上の問題はどこに報告すればよいですか。** [SECURITY.md](../../SECURITY.md) にある方法で、非公開で報告してください。公開の issue は立てないでください。
